## Why this is worth an operator page

- **These are the exact primitive grammars every smuggling engagement re-derives from scratch.** Ember documents three independent framing divergences (CL.TE, TE.CL via case-sensitivity, TE.TE via chunk-size lenience) and Traefik adds two *request-grammar* divergences (opaque request-target, trailer-sourced headers) that are rarely in standard wordlists.
- **The rootless request-target is the highest-value single record**: routing and path-scoped authz evaluated against a normalized `/` while the backend receives the raw target is a router/authz bypass channel, not just a cache-poisoning curiosity.
- **Trailer-sourced trusted headers are an under-tested surface on any proxy** — the sanitizer iterates the header map, the backend (or a framework that merges trailers) sees them as fields.
- **Header-name alias collapsing (dot/underscore/dash)** is the same parser-differential axis as the August 5 Traefik underscore-alias records; backends that derive variables from names collapse spellings the proxy treats as distinct.

## Validation workflow (authorized scope only)

!!! warning "Lab backends and single-connection canaries only"
    Test only against owned stacks in authorized scope. Use single-connection, self-contained canaries (one request, one response marker), never cross-user desync, cache poisoning of shared entries, or auth-boundary mutation on production. Record raw bytes on both sides of the proxy.

1. **Framing differential harness.** For each origin behind each intermediary, send one connection with: `Transfer-Encoding: chunked` + `Content-Length` (CL.TE); `Transfer-Encoding: Chunked` (case), `chUnKeD`, obfuscating whitespace variants (TE.CL); `+5`, ` 5 `, signed chunk sizes (TE.TE); and the opaque-form request-target `GET http:http://<owned-vhost>/admin HTTP/1.1`. Compare the two views: what the front normalizes/routes vs the raw target/body the backend echoes from an owned no-op route.
2. **Trailer smuggle probe.** Send a chunked request whose final chunk carries `X-Forwarded-Prefix` / `X_Auth_User` / `X.Auth.User` trailers; confirm whether the backend framework surfaces them as request headers or variables. Evidence is the echoed field name/value, not a privilege change.
3. **Static-route decode check.** Request `/%2F..%2F..%2F<canary>` and `%5C` variants against static handlers; prove only with synthetic classpath/resource canaries outside the configured base — never config files or key material.
4. **Client-side cookie jar audit** (for Scala services acting as SSRF-capable fetchers): verify domain-match anchoring with two owned hosts (`owned-a.example` vs `xowned-a.example`) and a server that answers `Set-Cookie: ...; Domain=owned-b.example`.
5. Report only framing/decision mismatch evidence with raw-byte captures; stop at the boundary.

## September 16 follow-up: Traefik HTTP/3 silently drops response timeouts (GHSA-7ghq-v6jf-g56c)

`respondingTimeouts.readTimeout` (default 60s, documented as bounding the time to read the full request including body) is **not applied to HTTP/3 entry points**. The deadline is enforced on the TCP connection, which cannot reach a QUIC stream, and Traefik's HTTP/3 server was constructed with no timeout at all. An unauthenticated client trickling a request body at negligible cost holds one request — and one upstream connection per request — open indefinitely; backends with bounded connection pools are the pressure point. Regression window: v2.8.2 onward (a quic-go API change removed the embedded `http.Server` that carried the timeouts); affected lines v2.8.2–v2.10.x and v3.0–v3.6 are unpatched on-line, fixes land in v2.11.56 / v3.7.12.

Operator value:

1. **Timeout-config parity across transports is a testable invariant.** On any proxy in scope, send one slow-drip body canary on HTTP/1.1, HTTP/2, and HTTP/3 to an owned no-op route and compare when the proxy gives up. A timeout configured and echoed in config but unenforced on one protocol is the finding — the same "validated on one path, enforced on none" axis as the header/framing items above.
2. **Version fingerprinting beats config assumptions**: v2.8.2+ through the fix releases all silently ignore the documented behavior, and most maintained lines carried it for years. Capture protocol negotiation, config excerpt, and both transports' deadline behavior in the evidence set.
3. Keep any slow-body check to a single self-contained connection against an owned route; the DoS class is real but the durable report is the enforcement gap, not resource exhaustion on a shared front-end.

## September 17 follow-up: Sanic chunked-trailer smuggling and oRPC reflected `Vary` (2 GHSAs)

[GHSA-wmj6-g64g-j7q5](https://github.com/advisories/GHSA-wmj6-g64g-j7q5) / [CVE-2026-85078](https://nvd.nist.gov/vuln/detail/CVE-2026-85078): Sanic's HTTP/1.1 chunked handling does not fully consume the `trailer-part` after the terminating `0\r\n` chunk, so attacker bytes left in the connection buffer are parsed as the start of a new request on the keep-alive connection. The verified PoC produces **two responses from one TCP send**: the expected `405` for the outer `POST /` plus a `200 OK` for a `GET /` hidden in the trailer area; changing the leftover `GET` to `:GET` shifts the second response accordingly, proving trailer-consumption error rather than legitimate pipelining.

Operator value: this extends the framing battery above with a fourth primitive grammar — **post-terminal-chunk leftover bytes** (`0\r\na:GET /admin ...`). It is distinct from CL.TE/TE.CL/TE.TE: the outer request frames *correctly*, so validators and intermediaries that only reconcile `Content-Length` vs `Transfer-Encoding` see nothing anomalous. Test one self-contained connection per origin: chunked body terminated by `0\r\n` followed by a short trailer-name-prefixed request line, and count response blocks on the socket. Evidence is two response blocks from one send against an owned route — never cross-user desync or cache mutation.

[GHSA-j9v4-rhgr-4m5f](https://github.com/advisories/GHSA-j9v4-rhgr-4m5f) / [CVE-2026-77360](https://nvd.nist.gov/vuln/detail/CVE-2026-77360): the oRPC CORS plugin copied the **request's** `Vary` header onto the response instead of treating `Vary` as response-only, letting a client inject arbitrary cache-key directives into shared caches/CDNs in front of the server and skew CORS enforcement for other clients (fixed `@orpc/server` 1.14.8). Validation stays lab-only and passive: send one request with an inert `Vary: X-Owned-Canary` to an owned endpoint behind an owned caching layer and record whether the value survives into the cached response's header map — header-survival evidence only, no poisoning of shared entries. Reusable axis: response headers that steer cache keys (`Vary`, cache-control passthroughs) must never be sourced from the request — same request-to-response reflection family as the header-alias items above.

## September 17 follow-up: RabbitMQ amqp091-go frame desync and URI re-parse confusion (2 GHSAs)

The 2026-09-17T17:04Z amqp091-go publication batch adds two protocol-grammar records that extend the framing-divergence battery to AMQP wire parsing:

- [GHSA-c5pq-fr2g-9jpf](https://github.com/advisories/GHSA-c5pq-fr2g-9jpf): `readLongstr` accepts a length field above `0x7FFFFFFF` and takes a silent-error path that **returns `("", nil)` without consuming the declared bytes**. The reader cursor never advances, so `readTable` keeps iterating with broken alignment — subsequent attacker payload bytes are reinterpreted as AMQP frame headers. This is a **server-to-client desync**: a malicious AMQP server (or MitM on a non-TLS amqp:// leg) riding a client into parsing attacker-chosen frames; the durable test is that error paths in length-prefixed parsers must consume-or-abort, never return success with unconsumed input. Audit rule for any length-prefixed codec you consume: send a maximal/negative/overflow length and check whether the connection terminates or continues with a shifted cursor — frame-injection state is the positive, not a crash.
- [GHSA-465g-fh3v-9jw4](https://github.com/advisories/GHSA-465g-fh3v-9jw4): TLS cert/key paths are appended to the connection URI query string by **string concatenation without `url.QueryEscape`**; a path containing `&`/`=` (e.g. from an env-sourced or workflow-sourced filename) injects additional query parameters that **overwrite legitimate settings** when the URI is re-parsed via `ParseURI` — later-wins lets an attacker-controlled value replace `keyfile`/other config. Same serialize→re-parse round-trip family as the rclone archive-join and Netty delimiter items: values must be escaped for the container they are embedded in, and any build-string-then-reparse pipeline is an injection surface. Proof pattern: a lab URI whose cert-path segment carries a `&param=canary` fragment, evidence is the parsed struct's overwritten field.

Tracked from the same batch without promotion: PLAIN credentials retained in exported `PlainAuth` struct fields (log/APM leak hygiene, no remote boundary), QoS signed-to-unsigned casting, missing TLS minimum version, sub-spec frame-size DoS, unbounded body allocation DoS, malformed field-length DoS.

## September 21 follow-up: Quarkus security-matcher vs dispatcher path-normalization split (GHSA-pw2v-hfg7-72m6)

[GHSA-pw2v-hfg7-72m6](https://github.com/advisories/GHSA-pw2v-hfg7-72m6) / CVE-2026-87743 (CVSS 7.5, Quarkus HTTP security, published 2026-09-18, surfaced via the updated feed 2026-09-21): **the security annotation matcher and the JAX-RS/request dispatcher normalize paths differently** — craft a URL the security matcher classifies as public that the dispatcher then routes to a protected endpoint → authorization bypass.

- This is the Quarkus instance of this page's standing rule: the security decision and the routing decision are two parsers over the same path string, and any divergence in percent-decoding count, trailing-slash, double-slash, matrix-parameter (`;jsessionid=`-style), or case handling between them is the bypass.
- Replayable battery on any framework where authz matching ≠ dispatch (already proven on Sanic, Traefik StripPrefix, Keycloak versioned route families, Airflow alternate mounts): for each protected route, request the same handler via `%2e`, `%252e`, `//`, `/;/`, `/.`, trailing `/`, mixed-case segment, and suffix-extension forms; the positive is **matcher-verdict(public) × dispatcher-route(protected handler response)**. Capture both verdicts — a 401/403 on every variant is only a negative if the protected handler is proven reachable by the baseline path in the same session.
- Framework-fingerprint first: Quarkus reveals itself via `/q/health`, `/q/metrics`, `/q/openapi` (unauthenticated by default on many builds) — those endpoints double as the version/recon probe before the normalization battery.

## September 22 follow-up: Traefik BasicAuth singleflight reintroduces a concurrency-only timing oracle + Tinyauth case-mismatch ACL (2 GHSAs)

- **Traefik v3.6.11–3.7.12 BasicAuth username-enumeration oracle** (CVE-2026-88010, [GHSA-8fcf-v89g-xpg6](https://github.com/advisories/GHSA-8fcf-v89g-xpg6), fixed 3.7.13): the middleware coalesces concurrent credential checks via a `singleflight.Group`, and since v3.6.11 the **dedup key was built from the submitted password plus the stored secret** — so a nonexistent username collapses onto one shared key while each real username gets its own. Fire a leader request plus probe requests inside the in-flight window: probes for *existing* usernames compute their own bcrypt (slow), probes for non-existent ones get served the leader's coalesced result (fast). Unauthenticated username enumeration — **only under concurrency**; the earlier sequential-probe oracle (GHSA-g3hg-j4jv-cwfr) was already hardened. Two operator rules: (1) when a prior timing fix exists, retest the *same control under concurrency* — cache/dedup/coalescing layers re-open the oracle the fix closed, and the dedup key's composition is the leak; (2) for enumeration against Traefik-fronted apps on 3.6/3.7, the battery is concurrent-burst probes (leader + followers on the same password), not sequential latency diffs. Positive evidence class: bimodal response-time distribution keyed on candidate usernames, captured against a lab Traefik with a known secret — no credentials needed beyond arbitrary submitted pairs.
- **Tinyauth forward-auth per-app ACL case mismatch** (CVE-2026-77560, [GHSA-328g-jx67-v94g](https://github.com/advisories/GHSA-328g-jx67-v94g), fixed 5.1.2): the per-app allowlist (`users`/`groups`/`ip`) matches the app **hostname case-sensitively** while hostnames resolve case-insensitively — request the app via a mixed-case host and the ACL lookup misses and **fails open**. Joins the case-sensitivity pair-sweep rule (Caddy `hide` vs APFS/NTFS, Sept 18): every case-sensitive string matcher over a case-insensitive namespace (hostnames, file paths, SQL identifiers) gets a mixed-case probe, and the ACL/allowlist family specifically needs the *misses-and-defaults-allow* test — a failed lookup that permits is worse than one that denies.

## October 2 follow-up: Anubis bot-protection bypass via client-supplied `X-Original-URI` (GHSA-6wcg-mqvh-fcvg / CVE-2026-62314)

Anubis (the challenge-based bot/proxy-protection middleware) v1.22.0–v1.25.0 lets **any HTTP client skip the challenge entirely with one request header**: the policy `PathChecker` reads `X-Original-URI` from the *request*, and if that header value matches a path-only ALLOW rule, the request is forwarded upstream with no challenge and no JWT check. The default policy ships path-only ALLOW rules (`^/\.well-known/.*$` in `keep-internet-working.yaml`), so the bypass works on the **default configuration** — the advisory's own PoC is `curl -H "X-Original-URI: /.well-known/x" https://target/` returning the real site title instead of the challenge page. The middleware chain never strips the header, and in reverse-proxy mode the attacker fully controls it (fixed 1.26.0 by stripping inbound).

Operator value for bug hunters and proxy-behind assessments:

- This is the **forged internal-routing header** family (X-Original-URL, X-Rewrite-URL, X-Forwarded-Path, X-Original-URI) applied to a *policy engine* instead of a router: any middleware that trusts a header naming "the original request" lets the client choose which policy bucket it is evaluated in. Standing sweep on every challenge/WAF/authz middleware: replay the same request with each known original-URI header variant set to an allowlisted path (`/.well-known/`, `/health`, `/robots.txt`); the positive is real upstream content with no challenge cookie issued — a one-line test with byte-evidence (challenge page title vs origin title).
- Fingerprint Anubis itself before testing: challenge-page interstitial, `/chip` favicon mutation, `status: 451` on block. Default-config ALLOW rules are enumerable from the public repo — the bypass regex list is public, so test all of them.
- Same request-to-policy decoupling as the Sept 21 Quarkus matcher-vs-dispatcher and Oct 1 APISIX non-canonical-path items: **the policy parser and the routing decision must judge the same normalized target**; a header that re-labels the target for only one of them is the bypass.

## October 5 follow-up: Fiddler Classic as a smuggling victim — the connection pool is the cross-user channel (2 GHSAs)

The Telerik Fiddler Classic <6.0.20262.10021 advisories are the desktop-debug-proxy instance of this page's framing-differential class, with one genuinely new channel: **the attacker and the victim share a local intercepting proxy instance**, and the proxy's own pooled upstream connections carry the smuggled state between them.

- **CL.TE desync with response-pool poisoning** ([GHSA-p3gc-87rm-gmjp](https://github.com/advisories/GHSA-p3gc-87rm-gmjp) / CVE-2026-77802, medium): Fiddler forwards duplicate conflicting `Content-Length` headers **verbatim** to the origin while framing the request body with only the **first** value. Against a non-RFC-9110-compliant keep-alive origin that parses the second `Content-Length`, this smuggles an additional request. The durable part is the readback leg: Fiddler returns the server connection to its **pipe pool after reading only the first response**, so the unread smuggled response stays buffered on the socket and is served to the **next session that reuses that connection** — response poisoning and cross-user response disclosure through the pool, not through the origin cache.
- **Front-end TE+CL desync, no vulnerable server needed** ([GHSA-xq67-hr2w-mm32](https://github.com/advisories/GHSA-xq67-hr2w-mm32) / CVE-2026-77803, low): a request carrying **both** `Content-Length` and `Transfer-Encoding` is forwarded with both headers present while Fiddler frames the body via `Transfer-Encoding` only — the leftover `Content-Length`-framed bytes are parsed as a second pipelined request on the reused client connection. One malformed request becomes two forwarded requests entirely inside the client→proxy edge; the origin never sees the anomaly as one request.

Operator value:

1. **Audit every proxy/interceptor you run or encounter for header-forwarding vs framing parity**: does it forward ambiguous `Content-Length`/`Transfer-Encoding` combinations verbatim while resolving the framing itself with first-value or TE-only rules? The mismatch (forward-verbatim, frame-locally) is the reusable vulnerability shape, present here in both legs.
2. **Connection-pool readback is a distinct desync impact channel.** On shared proxies (corporate boxes, shared dev workstations, CI egress proxies), one attacker's smuggled *response* survives into another user's session because the pool returns the connection before draining it. When testing an authorized shared proxy, evidence class = one self-contained canary connection producing a response that a *second* lab session receives; never weaponize against real co-users.
3. **Debug proxies are in-scope parser targets**, not trusted infrastructure: run the page's existing CL.TE/TE.CL/TE.TE/post-terminal-chunk battery against the proxy itself (loopback-owned origin) as part of toolchain assessments; the two-response-blocks-from-one-send positive applies at the client→proxy edge exactly as at the proxy→origin edge.

## October 6 follow-up: identity-parser differentials — proxy-addr trust-subnet math, PyMongo decode-before-split, Werkzeug device names (3 GHSAs)

- **proxy-addr treats `::ffff:10.0.0.0/8` as match-everything** ([GHSA-jqcg-44mw-7w3h](https://github.com/advisories/GHSA-jqcg-44mw-7w3h) / CVE-2026-90711, 9.1): writing an IPv4 trust subnet in IPv4-mapped IPv6 notation with a *short* prefix (`::ffff:10.0.0.0/8` instead of the correct `/104`) compiles with all-zero leading bits and matches **every IPv4 address** — every client is then a trusted proxy at hop 0, so Express `req.ip`/`req.ips` return attacker-chosen `X-Forwarded-For` values. No error at boot; the same block written in plain IPv4 behaves correctly, so the misconfiguration is invisible from the config file. Operator value: **XFF-spoofability probe belongs on every Express/Node app behind IP-based authz, rate limits, or geo-gates** — send `X-Forwarded-For: 10.0.0.1` from a public host and diff the access-control decision; a flipped decision means the trust subnet compiled wrong (or the app trusts the proxy list transitively). This is the header-trust sibling of the page's Anubis X-Original-URI leg: the client steers *which policy bucket it is evaluated in* — here by forging hop 0 itself. Also a config-audit grep for engagements with repo access: `::ffff:` prefixes with `/[0-9]{1,3}\b` prefix lengths under 96.
- **PyMongo percent-decodes the host section before splitting on `,`/`:`** ([GHSA-vp6j-j7w5-5xjj](https://github.com/advisories/GHSA-vp6j-j7w5-5xjj) / CVE-2026-96748, 6.5): `%2C`/`%3A` inside a hostname fragment survive app-layer URL-safety checks and become real seed-list delimiters inside the driver's parser — one app-visible hostname becomes two hosts, and the second can be attacker-infrastructure (topology discovery + auth against it = credential exposure). Decode-order split rule: **anywhere untrusted input is interpolated into a connection string, test encoded delimiters** — the parser that decodes-then-splits sees a different grammar than the validator that splits-then-decodes. Same dependency-vs-handler parse split as the Airflow `int()`-vs-pydantic leg, moved into the URI layer.
- **Werkzeug `safe_join` passes Windows device names with empty-ADS markers** ([GHSA-g6x2-hccm-hh4m](https://github.com/advisories/GHSA-g6x2-hccm-hh4m) / CVE-2026-102598): the prior device-name filter missed `NUL:`-style empty-ADS spellings on NTFS — `send_from_directory` opens the device and reads hang indefinitely. Incomplete-fix instance of the Windows-special-name class (LaraDashboard `..%5C`, Angular SSR sibling-directory, uv wheel traversal, Mako drive-letter `TemplateLookup` GHSA-5639 all landed the same week): **path-confinement helpers need a Windows parser-parity battery — device names, ADS markers, drive-letter URIs, backslash separators — reproduced on actual NTFS, not Linux CI.** Mako's drive-letter URI traversal in `TemplateLookup` is the template-loader twin of the same Windows path-parser gap.
- **Punk (Perl) routes HTTP/2/3 Extended CONNECT as GET, escaping the WebSocket Origin gate** ([GHSA-cmh9-2wr3-4x64](https://github.com/advisories/GHSA-cmh9-2wr3-4x64) / CVE-2026-104380, 0.48–<0.55): on HTTP/2 and HTTP/3 a WebSocket handshake is an *Extended CONNECT* request, which Punk's router matches as a **GET** — so it reaches every GET route, API operation, and mount. The Origin check runs **only when a websocket route matches**, so it never fires on this transport; the handler's normal 2xx response is accepted as the handshake response. A cross-origin page can then open a WebSocket to any path and learn from the open/error event whether that path returns 2xx — an unauthenticated, browser-driven route-status oracle across the whole GET surface. Operator rules: (1) **transport spelling is another enum-gated control axis** — when a security check is wired to a specific request-shape match (method, `:protocol` value, route class), test the alternate spellings that normalize onto the same handler: Extended CONNECT with `:protocol: websocket` vs a plain `websocket`-route upgrade vs HTTP/1.1 Upgrade; this is the sibling of the Oct 3 OpenAM PKCE `response_type` spelling leg, moved from OAuth params to HTTP transport. (2) Cross-origin WebSocket-open oracles are a **path-enumeration primitive** worth probing on any HTTP/2 or HTTP/3 framework: a 2xx-vs-non2xx open/error differential from the victim's browser defeats same-origin path-discovery assumptions. Framework-fingerprint rule from the Jetty page applies: if the stack parses HTTP/2/3, the pseudo-header/transport-shape battery is in scope, not just the HTTP/1.1 one.
