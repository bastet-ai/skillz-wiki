# Backstage wave (7 GHSAs): Scaffolder order-field secret oracle

**Wave in one line:** October 7 16:2xZ — TechDocs `mkdocs.yml` sanitizer allow-list misses, Scaffolder order-field secret oracle, and task-event/log secret reflection

Source: hourly offensive-security scan of GitHub Security Advisories, 2026-10-07 (published 16:22–16:25Z). Backstage (Spotify's developer portal) published seven advisories for `@backstage/plugin-techdocs-node` (fixed 1.15.4, releases v1.50.5/v1.54.6) and `@backstage/plugin-scaffolder-backend` (fixed 4.1.0). Fix commits are public, so the sanitizer gaps ship with their exact pre-fix shape.

Backstage is a high-value recon target class on its own: an internal portal that (a) builds documentation from **any registered repository's** committed `mkdocs.yml`, and (b) runs templated "scaffolder" actions with backend-managed credentials. An attacker needs only repo write access — routinely a much lower bar than portal admin.

## What the fix diffs prove

- **Sanitizer bypass #1 — allow-list membership.** Commit [`a7d995f`](https://github.com/backstage/backstage/commit/a7d995f11a5d27f0efbdbe8bb6c21b06988c79c9) deletes `extra_templates` from `ALLOWED_MKDOCS_KEYS` and adds a removal path with an opt-in override list. Pre-fix, any registered repo could set `extra_templates` — templates MkDocs renders outside the normal doc flow — straight through the sanitizer. The prior "fix" for CVE-2026-25153 was a key allow-list; the bypass was a key that *was on* the list but whose semantics the sanitizer never constrained.
- **Sanitizer bypass #2 — config stripped, extension kept (and vice versa).** Commit [`017ace5`](https://github.com/backstage/backstage/commit/017ace52d9b327ededc6704cf17799c875ae0f29) shows pre-fix `sanitizeMkdocsYml()` **explicitly whitelisted `pymdownx.snippets` (and the `pymdownx.snippets:SnippetExtension` spelling) as a string entry while stripping every other `:`-bearing name**, and did not scrub its *config*. The fix tests pin the exact dangerous config shapes: `base_path: /`, `restrict_base_path: false`, `url_download: true` — i.e. snippet inclusion from filesystem root and remote URL download at build time. The advisory adds that with old `pymdown-extensions` versions the inclusion stays reachable even after config sanitization (extension-default drift).
- **Order oracle.** Commit [`e673a86`](https://github.com/backstage/backstage/commit/e673a869449874a9169e8f89852e75e862011b93) adds `taskOrderFields = new Set(['created_at','status','created_by'])` and rejects anything else with 400. The new test literally uses `?order=asc:secrets` — the maintainers' own PoC field name is the secret column. Pre-fix, ordering by secret-bearing task fields leaks values through ordering responses.

## Operator playbook

1. **Find the portal.** Backstage frontends fingerprint on `/api/techdocs/metadata`, `/api/scaffolder/v2/`, `/api/catalog/entities` being public-ish. Note version from `/api/backend` metadata or bundle comments; the two fix bands (techdocs-node 1.15.4 / core 1.50.5–1.54.6, scaffolder 4.1.0) fingerprint per plugin, not per core.
2. **The `order` field is a free positive/negative control on any build.** Send `GET /v2/tasks?order=asc:secrets` and `?order=asc:created_at` with a low-priv token: fixed builds return 400 `InputError` on the former, 200 on the latter — a one-request patch-level probe. On vulnerable builds, treat every retained queued/failed task's secret-bearing fields as ordering-oracle inputs (compare position shifts across repeated requests; the advisory's own precondition list is retained secrets + target task visibility + known secret structure + repeated requests). Same sort-as-oracle class as the October 6 Payload join-sort leg.
3. **Task create/read as a secret relay.** The log leg's precondition is a denied action whose *input* carries a sensitive value — so enumerate which actions a low-priv user may invoke with attacker-influenced inputs, trigger denial, and read back the task log/event stream for reflected values. Report event-stream and log reflection as separate sinks; they were separately patched.
4. **Repo-commit → backend RCE is the portal's main edge.** With write access to *any* catalog-registered repo (every dev on the estate), craft `mkdocs.yml` tests **inside an authorized lab Backstage only**: (a) `extra_templates:` entries, (b) `pymdownx.snippets` with `base_path: /` / `url_download: true` pointing at an owned callback, (c) theme/plugin entries the sanitizer's allow-list predates. Proof boundary: prove *inclusion* (marker file content rendered into docs, or an owned-callback hit for `url_download`), never a reverse shell; `runIn: docker` is containment, not mitigation, per the vendor's own text.
5. **Local publisher path check.** On `publisher.type: local` deployments, probe the doc-serving endpoint for references outside the doc tree with synthetic marker paths in a lab; the cloud publishers are not affected, so fingerprint publisher type from response shapes before claiming the leg.
6. **Report framing.** The three TechDocs legs are one attack surface with three sinks (build RCE, build-time file/URL inclusion, serve-time file exposure). Bundle per-sink but lead with repo-write-to-backend-code-execution; the Scaffolder legs are read-side oracle + error-path reflection — do not collapse them into one "info disclosure".

## October 7 18:0xZ — second coordinated wave: the `markdown_extensions` name field is a callable-resolution sink, plus 20 more legs

Nineteen minutes after the first dump, Backstage published a second wave (17:58–18:05Z, ~23 advisories, same fix bands: techdocs-node 1.15.4, scaffolder-backend 4.1.0, catalog-backend 3.9.1, kubernetes-backend 0.21.8–0.21.10, backend-defaults 0.7.18/0.17.8, auth oidc-provider 0.4.20). ### The marquee leg: extension-name → Python callable

[GHSA-4488-j8vj-vqqv](https://github.com/advisories/GHSA-4488-j8vj-vqqv) / [CVE-2026-106510](https://nvd.nist.gov/vuln/detail/CVE-2026-106510) (with [GHSA-qmw3-745m-w99g](https://github.com/advisories/GHSA-qmw3-745m-w99g) / CVE-2026-106558, config-value constraints): commit [`02cd7cdb`](https://github.com/backstage/backstage/commit/02cd7cdbb) **ships the maintainers' own exploit fixtures** — `mkdocs_with_dangerous_extensions.yml` contains a `markdown_extensions` entry spelled `'subprocess:Popen'` with `args: ['/bin/sh','-c','id']` and another spelled `'os:system'`. Pre-fix, the sanitizer validated extension *names against a grammar it assumed was module paths*, but Python-Markdown resolves a `module:callable` entry by importing the module and **calling** the named attribute with the entry's mapping. So any authenticated user who can register a catalog entity gets arbitrary OS command execution on the TechDocs build host — no extension bug needed, the *name field itself* is the injection point. The same commit adds `DANGEROUS_EXTENSION_CONFIG_KEYS = {plantuml_cmd}` (an extension *option* that names a command — the `mermaid2`/plantuml family config-key route) and a key-level `ALLOWED_THEME_KEYS` set (`name/font/icon/.../palette/features`), meaning theme config sub-keys were previously passed through wholesale. Fixture `mkdocs_with_plantuml_cmd_hyphenated.yml` confirms the hyphenated spelling `plantuml-cmd` was part of the test matrix — spelling variants of dangerous config keys are explicitly in scope.

- **Durable rule: a "name/identifier" field consumed by a plugin-loader grammar that supports `module:callable`, entry-point, or factory notation is an execution sink.** Sweep every config surface that feeds Python-Markdown, MkDocs plugins, Hydra `_target_`, Jinja extension lists, logging `()` factories, or any `import + call` resolver, and test the callable-spelling of the field — not just unknown-name rejection. The sanitizer-allow-list bypass on this page (`extra_templates`, `pymdownx.snippets` config) is the same class one level up: keys the list *contains* whose *semantics* nobody constrained; this wave shows the values' grammar was also unconstrained.
- Probe ladder for a lab TechDocs build (authorized only, prove *invocation marker* e.g. `os:system` writing a canary, never a shell): (1) benign unknown extension name → rejection shape; (2) `'os:system'`-style name with a marker arg; (3) nested `plantuml_cmd`/`plantuml-cmd` option on a whitelisted extension; (4) `theme: <custom_dir-ish>` keys per commit [`911ca36f`](https://github.com/backstage/backstage/commit/911ca36f1) (source symlink validation landed alongside). The 400-vs-build-failure-vs-marker differential fingerprints sanitizer revision.

## October 7 20:2xZ follow-up: third Backstage wave (same fix bands) — overlapping proxy routes, Cloudflare Access audience skip, negative email-verification inversion, Sentry scaffolder action input validation

- **Inconsistent credential enforcement for overlapping proxy routes** ([GHSA-472h-9c5j-prrr](https://github.com/advisories/GHSA-472h-9c5j-prrr) / [CVE-2026-106456](https://nvd.nist.gov/vuln/detail/CVE-2026-106456), 4.8): proxy route-matching is longest/first-match-sensitive, and a more-specific route's credential requirement doesn't cover an overlapping less-specific sibling — same route-family drift as the r9ph deprecated-services leg, now proven on the *proxy* subsystem: enumerate every proxy prefix at every path depth and diff auth posture per prefix segment (a `/proxy/foo/bar` variant that matches a looser rule is the finding).
