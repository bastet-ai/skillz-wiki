# HTTP-client adapter guard-coverage drift — the axios 1.20 wave (Sept 30 GHSA cluster)

**Signal:** GitHub Security Advisories published a ~13-advisory Axios wave on 2026-09-30 (fixed in **1.20.0**) plus an Astro/Netlify allowlist bypass in the same window. One rule ties them: **security controls configured at the library's top level are enforced per-adapter, and the non-default adapters are where the guards are missing.** An application that picked a guard flag (`maxRedirects: 0`, `lookup`, `proxy`, `NO_PROXY`) did not buy the control — it bought the control *on the adapter that happens to read the flag*.

## Why this is durable

1. **Guard flags are adapter-scoped.** Enumerate every transport an HTTP client ships (http, https, fetch, http2, xhr, WebSocket-adjacent) and re-run the *same* guard test battery per transport: `maxRedirects: 0` against an owned 302, rejecting `lookup` against a denied host, explicit rejecting proxy, `NO_PROXY` exact-host vs CIDR vs loopback alias. A guard that passes on the default adapter and is silent on the others is the finding. Node 18+-era runtimes may *auto-select* the fetch adapter, so "we configured `maxRedirects: 0`" can be true config with no enforcement.
2. **Destination validation races the transport.** URL-string checks before the call are bypassed by anything that changes socket routing (`createConnection` gadget, h2 authority reconstruction, proxy/agent drop). The equivalence class to test: *config says A, socket reaches B.*
3. **Security-policy parsers carry their own crash/injection surface.** `NO_PROXY`/host-normalization code parses untrusted redirect targets — ReDoS via `Location` means a redirecting server can freeze the event loop mid-policy-evaluation.
4. **Generated allowlist regexes are codegen output — audit the artifact, not the config.** In any platform that compiles domain lists into regexes (CDN image allowlists, WAF rules, OAuth redirect matchers), fetch or reconstruct the generated expression and check anchors (`^...$`), backtracking semantics, and where the matcher runs. `.test()` without anchors is a substring matcher wearing an allowlist costume.

## Hunt ideas (authorized scope)

- Grep Next/Node services for axios usage where the SSRF posture depends on `lookup`, `proxy`, or `maxRedirects` — for each, determine the effective adapter (`adapter: 'fetch'` explicit, runtime auto-selection, `httpVersion: 2`) and replay the guard battery on that adapter against an **owned** redirector and an owned loopback listener. Evidence: adapter-vs-guard decision table.
- Where outbound policy uses `NO_PROXY`, enumerate destinations the operator meant to exclude (metadata IPs, RFC1918, loopback) and test CIDR entries with an owned listener on a host inside the range; the proxy-observability differential (does the proxy see the request?) is the verdict.
- In a lab process that already has a pollution primitive, add `createConnection`, `headers`, `toFormData` keys to the canary set and assert requests stay on-path. Where they don't, report the gadget chain (pollution source → axios sink → socket destination), fake credentials only.
- For any Netlify Image CDN (or analogous generated-allowlist image proxy): request `/.netlify/images?url=<owned-allowlisted-origin embedded in query/path of a target URL>` and confirm the fetch lands where the *parser* put it, using your own listener as the target. Response-as-image transformation limits exfil — prove reachability, don't chase data.
- Redirect-handling code paths in any client/proxy: fuzz `Location` with pathological host spellings for latency/crash before assuming policy parsing is inert.

## Validation boundaries

Owned redirectors, owned loopback listeners, fake credentials, and disposable deployments only. Never route through third-party proxy infrastructure to demonstrate NO_PROXY drift, never target cloud metadata endpoints to prove reachability, never leave polluted prototypes in shared processes. Upgrade target: axios **1.20.0**; `@astrojs/netlify` **8.2.4** (or `imageCDN: false`).

## October 1 12:31Z follow-up: same rule, JAXP factories (Camel Quarkus XSLT XXE)

[CVE-2026-88789 / GHSA-w8wc-5pf9-6ph5](https://github.com/advisories/GHSA-w8wc-5pf9-6ph5) (high, camel-quarkus-support-xalan 3.2.0–<3.33.3, 3.34.0–<3.40.0) extends this page's invariant from HTTP adapters to XML stacks: Apache Camel **applies `ACCESS_EXTERNAL_DTD`/`ACCESS_EXTERNAL_STYLESHEET` hardening to the `TransformerFactory` it creates**, but the XSLT support extension supplies its own **Xalan-J 2.7.x-backed factory and registers it as the JAXP default** — a factory that predates JAXP 1.5 and ignores those flags entirely. Result: any untrusted XML body that reaches the xslt component as a `javax.xml.transform.Source` gets local-file read / internal-network requests via external-entity declarations, *while the framework believes its hardening is on*. Audit rule: in any JVM stack with pluggable factory providers (JAXP TransformerFactory/SAXParserFactory, JCE providers, JDBC drivers), check **which factory instance the data path actually uses** — a legacy factory registered as the global default silently defeats per-framework security configuration. Proof stays lab-only: owned HTTP callback entity + local marker file in a disposable Camel/Quarkus service, never production integration endpoints.

Second same-shape record from the Oct 1 12:31Z wave: **Budibase AI table generation** ([CVE-2026-103757 / GHSA-2524-3r74-44wr](https://github.com/advisories/GHSA-2524-3r74-44wr), high, ≤3.41.0) — the platform ships a blacklisting fetch helper (`fetchWithBlacklist`), but `uploadUrl` in `packages/server/src/utilities/fileUtils.ts` calls **raw `node-fetch`**; an authenticated builder user's prompt to `POST /api/ai/tables` places an internal URL in an attachment column and the server fetches it, returning a presigned object-storage URL that carries the response (cloud metadata credentials named in the advisory). Guard-coverage sweep, application tier: grep the codebase for the direct client import (`node-fetch`, `got`, `requests`, `fetch(`) *alongside* the sanctioned helper — every call site using the raw client is an unguarded fetch leg, whatever the platform's SSRF posture claims. On closed-source targets the black-box equivalent: enumerate features that "attach a URL" and diff which ones obey your denylist canary (owned rebinding listener) versus which don't. Prove with lab-only canaries; never read real metadata.
