# Dancer2 guard semantics: header-name CRLF, hook refusal that still dispatches, and path-spelling differentials

Source: hourly offensive-security scan, 2026-09-22. Primary entries: GitHub Advisory Database [GHSA-vp8p-vxw7-c877](https://github.com/advisories/GHSA-vp8p-vxw7-c877) / CVE-2026-93711 (response header **names** keep CR/LF), [GHSA-qp5m-r6hx-rjhj](https://github.com/advisories/GHSA-qp5m-r6hx-rjhj) / CVE-2026-93710 (dying hook's refusal does not stop the route body), [GHSA-8fpv-59mj-6jfr](https://github.com/advisories/GHSA-8fpv-59mj-6jfr) / CVE-2026-93709 (AutoPage guard compares raw path, lookup canonicalizes), and [GHSA-fq22-f6q5-wv3x](https://github.com/advisories/GHSA-fq22-f6q5-wv3x) / CVE-2026-93712 (File route handler joins uncollapsed `..` onto `public_dir`). All four affect Perl **Dancer2 < 2.2.0** (fixed in 2.2.0); adjacent entry [GHSA-454c-c45p-5rr9](https://github.com/advisories/GHSA-454c-c45p-5rr9) / CVE-2026-76974 (SAP Fiori Launchpad unauthenticated crafted-link content load, medium).

Dancer2 is a niche Perl framework, but this four-advisory cluster is worth its own page because each advisory is a **different spelling of the same bug-hunting rule: a guard's verdict is computed over a different copy of the data than the one the sink consumes.** Sweep any web framework — not just Dancer2 — for these four shapes.

## Why it matters for operators

1. **Sanitize-the-value / forget-the-name is a response-splitting class, not a Dancer2 bug.** The header-name leg also shows up as `Content-Disposition` filename legs, cookie names, and custom `X-*` header names built from user input. Sweep: any place request data becomes a header **name**, then test with a raw CRLF + inert marker header; confirm whether the fronting server (plackup/starman/nginx) rejects or writes the key.
2. **Hook/filter-based enforcement has an exception path, and the exception path is the bypass.** Test pattern on any framework with before-hooks/filters/middleware that "die" or throw: send a request the gate refuses, then observe a **side effect that only the route body produces** (write to an owned sink, a job queue entry, a counter) while the HTTP response says refused. Response-status-vs-side-effect fidelity tables are the evidence artifact. Same family as the parameter-ABSENT axis — here the request is refused in words and executed in fact.
3. **Path-guard equivalence battery is reusable verbatim.** For every textual path comparison (`startswith`, equality against a deny dir, prefix checks): baseline, `//` double slash, `./` and `../` dot segments, `%2e%2e%2f` / `%2f` encodings, mixed case (on case-insensitive storage), trailing dot/space, and Unicode fold variants. The Quarkus matcher-vs-dispatcher split (Sept 21) and Grav lexical-collapse (Aug 25) pages collect the siblings; this adds guard-text-vs-lookup-canonicalization inside one handler.
4. **Fingerprint framework config posture before calling a leg dead.** Two of the four advisories are off-by-default features (`auto_page`, `File` in `route_handlers` with `static_handler: 0`). On Perl/Dancer2 targets, version-fingerprint (< 2.2.0) and, where visible, handler-config posture determine whether the battery applies at all — a 404 on `/../etc/passwd` may mean patched, default-config, or feature-off, which are different conclusions.
5. **SAP Fiori Launchpad crafted-link item** ([CVE-2026-76974](https://github.com/advisories/GHSA-454c-c45p-5rr9), medium) is sparse but names the reusable leg: an unauthenticated crafted link makes an authenticated browser load attacker-controlled external content from the launchpad origin — treat Fiori launchpad URL-parameter surfaces (`#/` targets, shell parameters) as open-redirect/content-injection sweep targets in SAP landscapes; prove with an owned redirector and header/URL capture only.

## Replayable validation boundaries (authorized labs / owned instances only)

1. Version-fingerprint first: confirm Dancer2 < 2.2.0 from error pages, banner headers, or dependency manifests; test AutoPage/File legs only if the feature config is present.
2. Header-name CRLF proof: lab route that echoes a request parameter into a header name; send `param=a%0d%0aX-Marker:%201`; record raw wire bytes (client-side capture) showing the injected marker header line, plus patched-version negative control. Never test response splitting through shared fronting proxies in production.
3. Hook-refusal proof: lab app with a `before` hook that dies on a marker token; send a refused request that would write to an owned sink (temp file, local queue); compare refusal status in the response against sink state. Inert writes only; never trigger real business actions.
4. Path-spelling proof: request the layout dir and `public_dir/../config.yml` only against owned/lab instances; stop at status + length + first-bytes fingerprint; do not retain or exfiltrate real config contents.
5. Fiori proof: owned redirector link only; capture whether the launchpad shell loads or proxies the external target; no session-token collection.

## Adjacent: Python stdlib `tarfile` data-filter verdict ignored on the link-fallback path

[GHSA-rj44-3777-mh5x](https://github.com/advisories/GHSA-rj44-3777-mh5x) / CVE-2026-87910 (medium, published 2026-09-11, surfaced in the 2026-09-22 updated feed): when `tarfile` extracts a link on a system that **doesn't support links**, it falls back to extracting the link's target member and runs the extraction **filter twice** — once for the member, once with the link location as name — and **one call's return value was ignored**. A filter (including stdlib `data_filter`) that returns `None` to deny an entry is therefore bypassed on exactly that fallback path.

Operator rule: **a security filter is only as strong as every call site honoring its return value, and fallback/error branches are where verdicts get dropped.** This is the mirror image of the Penelope `extractall()`-without-filter case on the [May 6 archive-extraction page](2026-05-06-archive-and-file-extraction-boundary-batch-ghsa.md): there the filter was absent; here it runs and its answer is thrown away. Proof stays bounded: disposable extraction root, one symlink member aimed only at a temp sibling canary, a platform/config where link creation fails (forcing the fallback), patched-Python negative control; never target real home dirs or credentials.

## Reporting heuristics

- Name each leg precisely: **header-name CRLF passthrough (value-sanitize/name-forget)**, **hook refusal with continued route-body execution (response-vs-side-effect divergence)**, **lexical guard vs canonicalizing lookup**, **relative-segment join file disclosure**, **extraction-filter verdict ignored on fallback branch**.
- Report status-vs-effect divergence with a fidelity table (HTTP status, body, sink state), not a narrative.
- For off-by-default handler legs, state the config precondition in the finding — that is what makes it reproducible.
