# Authentication-method precedence, HTTP-verb allowlist bypass, and ACL tie-break drift

A September 21 15:31–15:47Z GitHub advisory wave produced two clusters with durable operator axes — an **Apache Airflow credential-precedence trio** and a **MISP authorization-drift octet** — plus a lookup-ordering authz bug (Dogtag pki-core), an OAuth-state sentinel bug (Hatchet), and one fix-branch integrity lesson (Apache MINA). The reusable invariant across all of them: *the security control is a comparison or a lookup, and both comparisons and lookups have ordering, coverage, sentinel-value, and tie-breaking edges that ship untested.*

## 0. Two one-liners worth their own sweep

- **Dogtag pki-core ACL tie-break (CVE-2026-80110 / [GHSA-c24q-2g88-pp57](https://github.com/advisories/GHSA-c24q-2g88-pp57), 8.1):** the v2 REST ACL filter resolves a colliding literal-vs-wildcard ACL key by **lexicographic string comparison instead of specificity**, so a wildcard-mapped permission overrides a more specific literal one — `POST /v2/profiles/raw` (meant to need Administrator `profiles.create`) is authorized under the default Certificate Manager Agents group's `profiles.approve`. Sweep rule: on any rule-matching engine (ACLs, WAF rules, route matching, CAPAs), construct a deliberately colliding specific-general pair and see which wins the tie. Specificity should never be decided by alphabetical order.
- **Hatchet OAuth state sentinel collision (CVE-2026-61687 / [GHSA-phg3-3g28-wq9v](https://github.com/advisories/GHSA-phg3-3g28-wq9v), 7.1):** the OAuth callback **clears** session `oauth_state_<integration>` to `""` instead of deleting the key, and the later equality check accepts an empty `?state=` — an unauthenticated attacker binds an already-authenticated victim session to an attacker-chosen OAuth identity (login-CSRF → account fixation). Sweep rule: treat empty string, `null`, and sentinel defaults as equality-check operands — after completing one legit OAuth flow, replay the callback with `?state=` empty on any OAuth-enabled deployment.

## 1. Airflow: bearer-vs-cookie precedence inversion, logout that revokes nothing, tenant-blind asset events (3 GHSAs, 3.3.0–3.3.1, fixed 3.3.2)

| Advisory | Behavior |
| --- | --- |
| [CVE-2026-82355 / GHSA-9x6g-jfj6-r3jg](https://github.com/advisories/GHSA-9x6g-jfj6-r3jg) | A request carrying **both** a session cookie and an explicit `Authorization: Bearer` token is resolved — and **audit-logged** — as the *cookie's* principal. Bearer-over-cookie precedence is inverted by a cookie-derived-user cache path. |
| [CVE-2026-86473 / GHSA-9cmm-29p3-73gr](https://github.com/advisories/GHSA-9cmm-29p3-73gr) | The logout endpoint revokes **only** the token presented as the `_token` cookie. A bearer-header client gets a normal 200 logout response while its token stays valid for the full lifetime (default 24 h). |
| [CVE-2026-75158 / GHSA-pfr9-65p3-w9r9](https://github.com/advisories/GHSA-pfr9-65p3-w9r9) | `/assets/events` returns asset events for **every Dag**, no per-Dag authorization filter; the filter was also missing from the count query, so `total_entries` + pagination disclose hidden Dag existence even without reading rows. |

Operator axes:

1. **Credential-precedence table.** On any API with ≥2 auth channels (cookie, bearer, API key, mTLS), send a request carrying *two different principals simultaneously* and ask: which identity executes the action, and which identity lands in the audit log? A mismatch is principal confusion + misattributed audit records. Airflow's precondition chain is reusable: plant your own valid cookie in the victim's client via sibling-subdomain cookie tossing, shared-parent-domain XSS, or a shared workstation, then watch their bearer-authenticated calls execute as *you*.
2. **Logout is a state transition — verify it happened.** After logout, replay the captured bearer token against one harmless endpoint. A 200 after "logout" means the control only handled one presentation form of the credential. Sweep every credential-presenting transport (cookie, `Authorization`, query param, custom header) against logout/revoke/revoke-all-sessions endpoints; each is a separate revocation leg.
3. **Count-query oracle.** When list endpoints hide rows but the aggregate query skips the same filter, `total_entries` becomes an existence oracle for tenant-blind objects. Compare row count vs reported total with a two-team lab deployment — the delta is the finding even when you can't read a single row.
4. Airflow deployments already have pages on this wiki ([June 30 boundary page](2026-06-30-ai-artifact-airflow-boundaries-ghsa.md), Sept 17/18 verb-permission folds): the recurring Airflow class is **per-Dag/per-team scoping applied to the row path but not the count, cache, or lifecycle path**.

Reusable sweep order for any CakePHP/ORM-backed platform:

1. **Verb matrix on security-critical endpoints.** For login, MFA enrollment, password change, and logout: replay the identical request under `GET`, `PUT`, `PATCH`, `DELETE`, `OPTIONS`, `HEAD`, `TRACE`, and casing/whitespace variants. The MISP pattern is an *allowlist* check (`in_array($method, ['POST','PUT'])`) gating the security controls — every method outside the list silently skips them. The gate-control itself is the target: verify the control **runs** (rate limit trips, OTP challenge appears) rather than only verifying the action result.
2. **Key-scope gap on identifier writes.** Sweep every create/update flow that accepts `id` or UUID fields: does the code unset/reject caller-supplied primary keys before `save()`/`update()`? The MISP tell is the **adjacent loop that gets it right** — differential-read the sibling code paths around the vulnerable sink; the correct loop is the attack map for which entry point forgot.
3. **Delegation-axis drift.** Enumerate the axes along which the platform restricts access — API key vs session, event vs attribute, read-only vs read-write — and test requests that straddle two axes: read-only key + permission-restoring call; event access + restricted-attribute reference.
4. **Media-adjacent importers.** Validate-input-type-before-parse is routinely skipped on XML import endpoints: upload a file whose *name* says `.xml` but whose *content* is a path or URL payload.
5. **Low-role editors as XSS carriers.** Statistics/admin aggregate pages that render names of user-editable catalog objects (galaxies here) are stored-XSS collection points even though the editor role feels data-scoped.

MISP context note: this platform is threat-intelligence infrastructure — on authorized engagements, prove with synthetic events/reports/galaxies in a disposable instance; never touch production intel data, and treat any real session/credential material as out of scope.

## 3. Apache MINA: "fixed" version never got the fix (CVE-2026-94301 / GHSA-h355-27x9-rr7r, 9.8)

The `resolveProxyClass()` override closing the CVE-2026-47065 `java.lang.reflect.Proxy` acceptMatchers deserialization bypass was committed to the **2.2.X branch only**. The 2.0.29 / 2.1.13 artifacts *listed as fixed* — and everything after them (2.0.30, 2.1.14) — remain vulnerable, with the advisory publicly saying so.

Operator rules:

- **Version-fingerprint from the artifact, not the advisory table.** Confirm the fix's actual code (`resolveProxyClass` override in the class the fix touched — readable from the shipped jar) before trusting a "fixed in" row. Maintenance-branch lines are where fix-commit skew lives.
- **The public advisory is the exploit map.** A 9.8 advisory that describes the exact bypass the fix missed, with affected artifact coordinates published, is a ready-made target list — enumerate apps embedding `mina-core` 2.0.x/2.1.x deserialization endpoints.

## September 22 follow-up: Sync-in Server — three auth-endpoint drifts in one product

A single product (Sync-in Server v2.3.0) shipped all three recurring auth-audit shapes in one wave; use it as a checklist template for any NestJS-style login stack:

- **Complete 2FA bypass via the token endpoint** (CVE-2026-58269, [GHSA-92cr-jxw4-5wjg](https://github.com/advisories/GHSA-92cr-jxw4-5wjg), 8.1): `POST /api/auth/token` authenticates with username+password (`AuthLocalGuard`) then calls `getTokens()` directly — which never reads `user.twoFaEnabled` — while the *parallel* `POST /api/auth/login` path routes through `setCookies(user, res, true)` where the 2FA gate actually lives. Valid credentials + zero TOTP = unrestricted access/refresh JWTs. This is the alternate-transport authz-parity rule applied to MFA: **enumerate every endpoint that mints a session (login, token, device-flow, sync-register, CLI, API-key issue) and diff which ones consult the second-factor flag.** The cookie path enforcing 2FA proves nothing about the bearer path.
- **TOTP brute-force via lockout-counter no-op** (CVE-2026-58271, [GHSA-274f-6w77-8qm9](https://github.com/advisories/GHSA-274f-6w77-8qm9), 6.8): on the desktop-sync registration route, a *failed TOTP attempt* called the failure recorder on a code path where the branch wrote `passwordAttempts` back **unchanged** — counter never reached the threshold, lockout never fired. A guessed TOTP registers a sync client and returns a `{clientId, clientToken}` pair exchangeable for a session; with the known password the attacker can then call the 2FA-disable endpoint. Audit rule: the rate-limit/lockout control must be tested **on every consumer of the credential**, not just the login form — and the correct test is whether the counter *state advances* after N failures, not whether the endpoint eventually blocks (a fire-and-forget write-back can silently no-op).
- **Username enumeration timing oracle via short-circuit before the dummy hash** (CVE-2026-58272, [GHSA-29hq-23m2-2j47](https://github.com/advisories/GHSA-29hq-23m2-2j47), 5.3, *incomplete fix of a prior timing advisory*): the codebase already contains the standard defense — `comparePassword()` burns a bcrypt compare against a dummy hash when no hash exists — but `validateUser()` returns early when the user lookup comes back empty, so the nonexistent-user path **never reaches** the constant-time function. ~100ms bcrypt-vs-nothing differential. Reusable lesson: timing equalization lives or dies on the **call graph**, not the helper; when auditing any "fixed" enumeration advisory, trace every return path from the router to the sink and check each one actually passes through the equalized function. This is the fix-placement sibling of the MINA "fixed version never got the fix" pattern above.

Validation boundaries: disposable Sync-in instance, synthetic users with TOTP enrolled, and your own credentials only; for the timing check use lab-network latency controls and report median/response-time distributions, not a single sample. Never test lockout exhaustion against a shared instance (it will lock real accounts).

## September 22 follow-up: MISP second wave — dead-operator-precedence guards, unlockedActions CSRF, path-concat oracles, and parent-vs-child distribution drift

A second MISP wave (published 2026-09-22, ~14 advisories, `< 2.5.47` train) adds five new axes to the octet above:

- **Unauthenticated SSRF via an `unlockedActions` endpoint + PHP operator-precedence guard bug** ([CVE-2026-95679 / GHSA-95gm-v6rp-cf52](https://github.com/advisories/GHSA-95gm-v6rp-cf52)). `RequestHandlerComponent` auto-decodes XML bodies on all write requests; `Xml::build()`'s readFile guard is written `readFile && http || https` — `&&` binds tighter than `||`, so the **https branch bypasses the readFile check entirely**, and a bare HTTPS URL in the body is fetched server-side. The `cspReport` endpoint accepts XML content-type and is **unauthenticated by design** → unauth outbound-HTTPS oracle (internal probing, timing recon, side effects on internal endpoints). Two sweep rules: (1) the `&&`/`||` dead-guard pattern already canonized on the Sept 22 Dancer2 page and the WP wave — grep mixed-precedence boolean guards in validation code, they die silently; (2) **"unauthenticated by design" endpoints (CSP-report, webhooks, health) still execute the platform's full body-decoding pipeline** — an endpoint that needs no auth still inherits every parser feature (XML entity/locator fetching) the authenticated endpoints have. Probe CSP-report/webhook endpoints with each content-type the framework auto-parses.
- **CSRF-stripped *action* executors via framework allowlists** ([CVE-2026-95658 / GHSA-5fvj-qq2x-32vr](https://github.com/advisories/GHSA-5fvj-qq2x-32vr)): `moduleStatelessExecution` sits in CakePHP's `unlockedActions`, which disables CSRF **and** field-hash validation — on an action that runs a workflow module's `exec()` with caller input. An attacker's cross-origin form POST executed by a logged-in admin invokes module execution. Audit rule: dump every `unlockedActions`/CSRF-exempt list in CakePHP/Spring/other frameworks and ask whether any exempted action is *state-changing or executor-shaped* (webhooks legitimately belong there; module runners do not).
- **User-controlled strings concatenated into `file_exists()`/path checks = existence + type oracles** ([CVE-2026-95698 / GHSA-24qr-3pqh-xghm](https://github.com/advisories/GHSA-24qr-3pqh-xghm): org name from event import → `findOrgImage()` traversal, `../../etc/passwd` resolves outside the image dir, distinct error messages yield file-existence oracle; [CVE-2026-95703 / GHSA-f4j8-7jmm-g7jj](https://github.com/advisories/GHSA-f4j8-7jmm-g7jj): admin `__uploadLogo` runs `file_exists`/MIME/EXIF probes on a caller-supplied `tmp_name` **before** `is_uploaded_file()`; [CVE-2026-95701 / GHSA-c7hm-qgxh-6vgg](https://github.com/advisories/GHSA-c7hm-qgxh-6vgg): dead-but-instructive sibling). Sweep rule: any `file_exists`/`is_readable`/mime-probe whose path components include a DB field the caller can write (org names, display names, slugs) is a filesystem oracle even when no content is returned; differential error messages are the channel. The `tmp_name` shape is its own classic: **PHP upload handlers that probe before `is_uploaded_file()` accept arbitrary server paths** — test upload endpoints with non-upload `tmp_name` values pointing at lab marker files.
- **Parent-readable ≠ child-readable: enrichment queries skip the child's own ACL** ([CVE-2026-95683 / GHSA-83cf-9w8x-h48q](https://github.com/advisories/GHSA-83cf-9w8x-h48q)). The Overmind event view auto-fetches the most recent attached report using only the event ID, ignoring the report's own (more restrictive) distribution setting — and doesn't filter soft-deleted rows. This is the nested-ID axis with the check *inverted*: instead of "child trusted without parent check," it's "parent checked, child's *tighter* ACL never applied." Sweep every auto-enrichment/preview/aggregate fetch: does the query join filter on the child's own visibility columns, and does it exclude soft-deleted rows? Soft-deleted-object disclosure is its own recurring class — always request deleted IDs.
- **Verb-gated authorization check with a verb-permissive persistence layer** ([CVE-2026-95671 / GHSA-ph85-5rm4-24r5](https://github.com/advisories/GHSA-ph85-5rm4-24r5)): `CollectionsController::add()` ran the sharing-group authorization check **only on POST**, while `CRUDComponent::add()` persists on POST *and* PUT → `PUT /collections/add` creates a collection shared with an unauthorized sharing group. First verb-allowlist bypass *inside* this same product family's second wave — the September 21 rule ("verify the control *runs*, per HTTP method") now has a same-product second data point; add `PUT` to the verb-matrix test on every `add()`-shaped CakePHP endpoint.

Smaller items from the wave folded without separate rules: wildcard-ACL overmapping (`replaceSuggestionInReport` mapped to `*` permission while siblings require `perm_add` — the ACL-tie-break family above; diff the permission map of an action against its siblings' [CVE-2026-95685 / GHSA-385h-fw9f-cf6x]); `$force`-style "system paths" that skip ownership checks when triggered by ordinary user flows (org-metadata overwrite by SG editors via `captureOrg` [CVE-2026-95697 / GHSA-prf9-8cgh-75pc]); **JS-string-context encoding class** — `json_encode()` without `JSON_HEX_QUOT|JSON_HEX_TAG` inside a *single-quoted* JS string literal breaks out on `'` ([CVE-2026-95665 / GHSA-24x5-fh5v-x5g9](https://github.com/advisories/GHSA-24x5-fh5v-x5g9)), and raw `echo` inside a double-quoted JS string is the same bug with no encoder at all ([CVE-2026-95682 / GHSA-99m7-rm9g-j79h](https://github.com/advisories/GHSA-99m7-rm9g-j79h)); when probing injected-XSS candidates in PHP apps, test quote characters (`'` and `"`) separately per render context — a server-side "properly JSON-encoded" value is still injectable if the delimiter is a quote the encoder doesn't escape.

Tracked from this wave without publication: TOTP-branch disabled-user guard no-op via missing SELECT column (advisory itself says re-validation downstream makes it harmless), enrichment module-name silent fallback (availability-of-unintended-feature only), installer world-writable log, assorted reflected XSS singles without new render-context classes.

## September 22 evening follow-up: unregistered action verbs, ACL typos, and validate-then-cache invitation tokens

Three more authorization-drift exemplars from the Sept 22 18:33–19:57Z waves, all siblings of this page's core rule (authorization is a lookup/coverage problem, and coverage bugs fail open):

- **Deepstream `PATCH_MULTI` permission bypass** (CVE-2026-63116, [GHSA-89vx-jh4q-vg3w](https://github.com/advisories/GHSA-89vx-jh4q-vg3w), 8.8): the record permission engine maps allowed actions in a `RULES_MAP`; `PATCH_MULTI` was **never registered**, and the engine's "no rules found for this action" branch calls back with **allow**. Any authenticated minimal user writes arbitrary data to any record via WebSocket `{topic: RECORD, action: PATCH_MULTI}`. Operator rule: for any action-map/verb-registry authorization engine, enumerate **sibling verbs the registry omits** — read the map's keys from protocol/docs, then try every action verb not in the map. The fail-open default on "unknown action" is the bug; `PATCH` covered but `PATCH_MULTI` absent is the classic late-added-endpoint drift.
- **MISP ACL typo converts a permission string into nothing** (CVE-2026-95805, [GHSA-c2r5-m9w2-228q](https://github.com/advisories/GHSA-c2r5-m9w2-228q)): the ACL entry for `previewEventAttributes` references `theming_enabled*` (stray asterisk) instead of `theming_enabled`; the malformed key matches no real permission, so the action's access control malfunctions (bypass or deny depending on evaluation logic). Adjacent entry `previewEventObjects` uses the correct string — **diff adjacent ACL rows for spelling drift**. Sweep rule on any file-based ACL config (MISP, framework `acl.ini`, route-permission tables): grep for permission values that don't exist in the role/permission master list; an unmatched key is not "closed", it is *undefined behavior*.
- **Databasement validate-once invitation tokens** (CVE-2026-95654, [GHSA-9cq7-qg25-29v5](https://github.com/advisories/GHSA-9cq7-qg25-29v5), 7.4): the invitation flow validates the token only when the **acceptance page loads**, caches the authorization decision, and never re-checks token validity at the accept step. A leaked/forwarded invite link stays usable after the legitimate recipient has already accepted — the second accept **overwrites the account password**. Operator rule: for every token-gated flow (invite/reset/verify), run the **stale-token replay battery** — load the page, let the real use happen, then replay the cached-authorization accept step. Validation at render ≠ validation at effect; this is the page-load-vs-acceptance twin of the render-vs-process authz parity rule.

## October 2 late-wave follow-up: an auth plugin that fails open *upward* — leftover session attribute grants agent privilege (Dogtag EST)

- **Dogtag pki-core `CMCAuthForEST` fail-open to agent privilege** (CVE-2026-104988 / [GHSA-qgmm-v3v3-wff2](https://github.com/advisories/GHSA-qgmm-v3v3-wff2), 8.1): an EST fullcmc enrollment submitted via BasicAuth **without** an end-user client certificate leaves the SSL_CLIENT_CERT session attribute holding the **EST subsystem's own agent certificate**, and downstream authorization judges the request as agent-privileged → an authenticated EST user obtains CA-signed certificates with **arbitrary subject names**. This page's fail-open family with a new carrier: the missing credential doesn't default to *anonymous*, it defaults to *the highest-privileged identity that previously passed through this servlet/session*. Two sweep rules: (1) on any auth plugin wrapping a shared subsystem (EST/ACME/CMP gateways behind an RA, proxy-authenticated admin consoles), submit the request through the plugin path **without** the expected credential and observe which identity the audit log names — a log line crediting the subsystem's agent cert is the finding; (2) session attributes set by an upstream component are ambient authority: test the downstream route directly *and* through the upstream with and without per-request credentials, and diff the granting identity. CA-side proof stays lab-only: disposable CA, synthetic subject names, never production PKI issuance.

## Evidence and reporting checklist

- [ ] Airflow proofs use two lab principals (cookie-attacker + bearer-victim), synthetic tokens, and record *which identity the audit log shows* as the primary evidence.
- [ ] Post-logout replay proofs state token TTL and use only synthetic tokens; never retain real session material.
- [ ] Verb-matrix tests run against a disposable instance with security controls observable (rate-limit counters, challenge presence), never against shared/production MISP.
- [ ] IDOR/reparenting proofs use two lab events + synthetic report rows; report the exact field (`id` vs `uuid`) reaching `save()`.
- [ ] SSRF/file-read proofs use owned callbacks and lab marker files.
- [ ] MINA claims cite the artifact coordinate **and** the decompiled presence/absence of the override.

## September 22 evening follow-up: async-authorization bypasses and subject-kind coverage gaps (Sept 22 20:34–20:40Z sync wave)

- **Unleash missing `await` on a permission check** (CVE-2026-77426, [GHSA-72h8-wp98-7hch](https://github.com/advisories/GHSA-72h8-wp98-7hch), high, fixed 8.0.3): `POST /api/admin/segments/strategies` is route-level `permission: NONE` and self-checks via `this.accessService.hasPermission()` — **without `await`**. `hasPermission()` returns `Promise<boolean>`; a Promise object is always truthy, so `if (!hasFeatureStrategyPermission)` never fires → any authenticated user reaches the admin sink. Same wave: cross-project IDOR on other admin routes + a project member reordering **any other project's** activation strategies (CVE-2026-77425, [GHSA-5ffh-6f9q-5hhr](https://github.com/advisories/GHSA-5ffh-6f9q-5hhr)) + clone-feature from unreadable projects (CVE-2026-76910, [GHSA-8xcj-9hfr-fh9j](https://github.com/advisories/GHSA-8xcj-9hfr-fh9j)). Where the Oct 7 Candlepin leg showed ANY-of where ALL-of was intended, this leg shows scope-set combination widening the union of grants — scoped assignments (environment/tenant/project scopes) composed additively instead of intersecting against the intended grant.

- Sweep rule that now has two independent product instances: for any RBAC system where a permission can be granted **once per scope** (per-environment, per-team, per-tenant), build a scope-combination matrix per permission — grant in scope A only, grant in scope B only, grants in A+B — and compare the effective action set against the intersection semantics the UI implies. Over-union shows up as scope-A credentials working in scope-B targets. Vendor advisory [SA2026-12](https://advisories.octopus.com/post/2026/sa2026-12). Same-product re-sweep rule holds: the Oct 7 role-self-modification leg and this Oct 8 scoped-aggregation leg were found in different sweeps of the same product weeks apart — when one Octopus authorization bug lands, re-audit the whole permission-evaluation path.

## October 8 15:3xZ follow-up: omitted-parameter default-match ATO (Integrics Enswitch) and client-side-only admin auth (mJobTime) — the absent-value battery on telephony and job-scheduling admin panels

Two fresh instances of the empty/absent-value-selects-permissive-branch family (389 DS SELFDN empty DN, DataPower empty-password LDAP same-day):

- **Integrics Enswitch 3.13–4.4** ([GHSA-qxpp-mcfv-63xp](https://github.com/advisories/GHSA-qxpp-mcfv-63xp) / CVE-2026-107640, 9.1): `/api/json/user/password/update/` **requires a `reset` parameter to be present-and-valid only when a password reset is pending** — omit it entirely and an account with **no pending reset** (whose stored `reset_key` is the empty default) matches the defaulted-empty comparison, so the password is changed with zero authentication. Two compounding defects worth separating: (1) an **optional-in-name control** (`reset`) whose absence silently selects the pass branch instead of the deny branch, and (2) **empty-stored-state == empty-supplied-state** collision. Sweep rule: on every password-change/reset/verification endpoint, run the **absent-vs-empty-vs-garbage-vs-valid decision table** for each security parameter (token, code, key, nonce): present-valid and present-garbage should both be denied without a pending state; ABSENT must never be the one shape that succeeds. Pair with username enumeration (this product allowed it) = admin ATO from a single unauthenticated POST. Enswitch is a widely deployed SIP/PBX platform — its `/api/json/` family is a standing recon target class on unified-comms engagements (lab PBX only).
- **mJobTime through 15.7.3.32** ([GHSA-fw9h-fgmp-7fx3](https://github.com/advisories/GHSA-fw9h-fgmp-7fx3) / CVE-2026-9209, 9.8): the Login.aspx admin panel's `runQueryButton` postback and `exportSqlQuery_Server` PageMethod **execute caller-supplied SQL as DBA/sysadmin against the backing Sybase SQL Anywhere database with no server-side authentication beyond a client-side `sessionStorage` flag** — `xp_cmdshell`/`xp_read_file` reachable ⇒ single-HTTP-request pre-auth RCE as LocalSystem. The durable rule is the trivially-general one: **any state the server does not re-check is not a control** — `sessionStorage`/`localStorage`/disabled-button "auth" is fingerprintable by simply POSTing the handler directly (bypass the page, hit `Login.aspx` methods with the same parameter envelope). On any legacy .NET WebForms-style appliance: enumerate `__VIEWSTATE` postbacks and `PageMethod` endpoints independent of the login flow; a SQL-exec box exposed at 9.8 means the admin panel was never authenticated server-side at all.

Cross-ref: the absent-param-branch rule also appears in the Sept 17 SPIP Crayons leg (omitting `secu_` selects an unconditional-TRUE dispatcher branch) — three products, one bug class: **controls that only fire when their parameter is present fail open on absence.**

## October 9 06:31Z follow-up: FalkorDB Bolt endpoint — auth delegated to a backend error string, parser live while the feature is "off," and ASSERT-only bounds checks (7-GHSA wave)

FalkorDB (graph DB shipped as a Redis module; a Neo4j **Bolt** protocol listener rides a separate `BOLT_PORT`, disabled by default) published a coordinated seven-advisory wave fixed 4.20.0 / 4.18.x. This is the same product whose Sept 21 memory-safety six-pack was tracked here without publication — the **same-product re-sweep rule** paid off: the second wave contains a genuine new authorization plane, not just more decoder crashes.

- **Auth gate keyed on ONE backend error string; every other error means "authenticated"** ([GHSA-f2fq-5xqf-g726 / CVE-2026-107910](https://github.com/advisories/GHSA-f2fq-5xqf-g726), critical): `is_authenticated()` decides whether a password is required by issuing an **empty AUTH command to Redis** and treats only `WRONGPASS` as "a password is required." Any other error reply — `LOADING` while the dataset loads, `MASTERDOWN` during replication failover, `OOM` under memory pressure — classifies the Bolt client as **already authenticated**, giving unauthenticated graph-query execution. New sub-axis for this page's gate-failure taxonomy: the gate has no failure path of its own — it **delegates the decision to a backend call and then pattern-matches one error token**, making every *unrecognized* backend state an allow branch. Sweep rule: wherever an auth gate shells a decision into a backing store/cache/replica, enumerate the backend's full error vocabulary (loading, failover, timeout, quota, disconnect, shutdown-in-progress) and ask which spelling returns "allow"; lab triggers for the transient states are real — bulk-load a dataset, kill the master mid-failover, apply memory pressure against a disposable instance. Timing-window corollary: `LOADING`-window access is *scheduled* attack surface — a restart-to-load is operator-predictable.
- **Parser surface active even when the feature flag is off** ([GHSA-g4x7-54hf-p7f3 / CVE-2026-107911](https://github.com/advisories/GHSA-g4x7-54hf-p7f3), high): the `_read_flags` handler accepts a `--bolt` argument on the **normal Redis command path**, casts the following Redis string object to a Bolt client struct with no origin check, and result-set code dereferences pointers read from that object — and the argument **is parsed even when the Bolt endpoint is disabled**, so default configurations are affected. Fingerprint rule for any multi-protocol server: config gates routinely disable the *listener* but not the *parser/handler code* behind it; probe feature-flag arguments (`--<feature>`, protocol-named flags, alternate-protocol keywords) on the primary port even when the feature port is closed. Type confusion via "cast attacker string to internal struct" is the memory-corruption tail of the same finding.
- **ASSERT()-only bounds checks, compiled out in release builds** ([GHSA-jpx9-94mp-7xhq / CVE-2026-107908](https://github.com/advisories/GHSA-jpx9-94mp-7xhq) critical — Bolt `RESET` with attacker-chosen 16-bit chunk size moves up to 64 KiB backwards past the read buffer; [GHSA-x67x-q5pm-p9h7 / CVE-2026-107909](https://github.com/advisories/GHSA-x67x-q5pm-p9h7) high — WebSocket frame with 64-bit extended payload length XORs past the receive buffer; [GHSA-fmqx-854h-cfff / CVE-2026-7826](https://github.com/advisories/GHSA-fmqx-854h-cfff), [GHSA-fwp9-2ghh-pw8g / CVE-2026-7827](https://github.com/advisories/GHSA-fwp9-2ghh-pw8g) critical, [GHSA-gxrc-33jm-h5ch / CVE-2026-5759](https://github.com/advisories/GHSA-gxrc-33jm-h5ch) critical on the RDB replication-stream decoders — reachable against any passwordless Redis-protocol instance): four legs where the *only* bounds/validation check is `ASSERT()`, which release builds delete. Recon/audit rule for C projects: grep the target's parse paths for assert-macro validation (`grep -n "ASSERT\|assert(" src/`), and treat "has a check" findings from source review as *build-mode-dependent* — differential-test the same malformed input against a debug build and the shipping release build before trusting the vendor's claimed control. The three RDB-decoder legs pair with the June GDB/Redis-replication precedent: replication command families (`SYNC`/`PSYNC`/`RESTORE`-class) are an under-swept attacker-controlled deserialization channel on any exposed, passwordless Redis-shaped service.
- Surface inventory for engagements where FalkorDB or Redis-module stacks appear: three separately fingerprintable listeners (Redis port always, `BOLT_PORT` when enabled, replication channel on the Redis port) × two protocol parsers (RESP flags path, Bolt/WebSocket framing) — enumerate all three before concluding "feature disabled = surface absent."
