# Siemens OT patch-day wave: PLC web-server trace-file ingestion XSS, RUGGEDCOM CROSSBOW metadata SQLi + credential queries, and unauthenticated memory reads on APOGEE building controllers

**Wave in one line:** A 2026-10-13T12:32Z coordinated GHSA batch across the Siemens portfolio — **eight stored-XSS legs where the injection vector is an imported engineering/trace file consumed by the SIMATIC S7-1500 web server** (three critical, chain stated by the vendor as "JavaScript in the engineer's browser performing PLC operations within the user's authorization"), a **ten-leg RUGGEDCOM CROSSBOW < V6.0 cluster** (SQL injection through plain metadata fields, admin-credential retrieval via internal DB queries, and a family of missing server-side authorization checks), **four unauthenticated web/FTP service legs on APOGEE/TALON building controllers** (one of which reads device memory), plus Industrial Edge App Publisher Node-frontend RCE, WinCC database-role privilege escalation, and a **vendor test key shipped inside UEFI Secure Boot databases** on SIMATIC IPCs.

**Signal:** OT management planes were flagged as a recurring target class on the [Sept 16 OT update-key page](2026-09-16-secret-server-identity-crypto-boundaries-and-ot-hardcoded-update-keys-ghsa.md) and the Oct 8 Brocade SAN page. This wave adds the durable OT lesson: **the engineering workflow itself — file imports, bulk exports, diagnostics viewers — is the attack surface, and it is reachable through people who legitimately hold low-privilege read rights.**

## Why this is durable operator guidance

1. **Engineering-file ingestion is a first-class web attack surface in OT tooling.** The S7 trace-file legs are the cleanest statement yet of the pattern: a SCADA/PLC web server that parses CSV/diagnostic files uploads from engineers and renders their fields (comments, names, markers, visual properties) **without escaping** in the same authenticated web UI that writes to the PLC. The advisory states the end state in one sentence: attacker JS runs in the victim's browser session and **performs PLC operations through the web server within the victim's scope**. No PLC protocol bug, no firmware bug — the browser is the pivot into the control plane.
2. **Eight legs = one sink, the whole field inventory.** Same Trace page, eight ingress fields (comments, marker data, signal names in menus, names inside *error messages*, calculated-signal data through two file types, visual properties). This is the vendor enumerating its own missed render sites — use it as a template: when you find *one* reflected field in an ingestion viewer, every sibling field on that page and in adjacent error/menu/render paths is untested until you test it.
3. **The required privilege is the lowest one that touches the workflow.** "Read diagnostics" is a help-desk/junior-engineer right; the phishing lure is a plausible trace file ("can you load this capture?"). In OT scopes, **file-swap between engineers is normal operational traffic** — far less suspicious than any credential phish. This is the OT twin of the SmarterMail iCal-leg and the Office document-parsing family: the ingested *analysis artifact* is the payload carrier.
4. **Management-platform metadata fields reach SQL.** CROSSBOW's five SQLi legs all inject through *names and labels* — facility names, device groups, a firmware-upload **filename**, notification values, file labels. Rule: in appliance management consoles, bulk import/export workflows and filename fields are the least-parameterized code paths; the export workflow in particular concatenates selection/filter metadata into queries. Then the credential leg (89199): configuration items readable through internal DB queries disclosed **administrative credentials for other internal systems** — the management platform is a credential cache, the same vault-target rule as the Oct 13 msf-ws page.
5. **Building-management controllers speak unauthenticated services.** APOGEE's four legs are pre-auth web (memory-read + DoS via multipart + DoS via upload) **plus FTP DoS** on building controllers, with MBC/MEC lines listed "All versions" — nothing to patch to for those. For red-team building-access recon: these controllers live on OT/building networks that are usually blandly reachable; an HTTP length-probe that returns device-memory content, or banner-level FTP presence, is passive version/fingerprint material. Same family as the Sept 16 OT page — building automation is forgotten management infrastructure.
6. **A desktop OT tool with a Node-integrated renderer turns any render XSS into code execution.** App Publisher (xm4r): backend data renders unsanitized into a UI glued to Node.js → vendor itself says "execution of arbitrary JavaScript ... RCE on the victim's machine." Pair with its no-cert-validation leg (rc9q): you can also just be *on path*. This is the Electron/Edge-side echo of the Oct 8 HmiServer "renderer is not a safe place" cluster: audit the renderer→host bridge of every engineering desktop tool you install, and its TLS verification flags.
7. **Secure Boot is inventory, not a checkbox.** f9v9: factory-shipped **test keys in the UEFI signature database** on SIMATIC IPCs. Rule for hardware engagements: read the key databases (`db`, `dbx`) — a vendor test key means "Secure Boot enabled" is a lie, and the boot-chain attacks this page family already carries (bootkits, firmware implants) become bootable-and-persistent. Physical/admin access yields the full CIA triad claim the vendor itself states.
8. **Missing-authorization-check family on a management plane = free session control.** CROSSBOW 89202/89205/89206: minimal-privilege users disconnect admin sessions, schedule special operations, and retry/stop/delete scheduled tasks. When one console shows missing per-action server-side checks, enumerate **every verb with a side effect** — session control, scheduling, task state — under the lowest test account. Post-auth access-boundary testing, not generic SQLi/XSS hunting.

## Validation workflow (authorized scope only — lab PLCs/controllers or explicit written approval)

1. **Trace/ingestion viewer sweep (lab S7 web server only).** Own a disposable S7-1500 (or lab emulator with the web server) and a read-diagnostics lab account. Build one CSV trace fixture per rendered field from the table (comment, marker, signal name, calculated-signal name aimed at an *error* path, calculated data, visual property) carrying a unique inert DOM marker (harmless `<img onerror>` to an owned listener). Import once per field; record which field fires. Prove **scope**: fire a read-only PLC operation from the marker context to show the JS inherits the session's PLC rights; never write to any live process variable, never target a production plant's engineering workflow.
2. **Ingestion-field sibling battery.** Wherever an OT tool imports a file (trace, project export, tag CSV, PLCopen/LADDER artifacts, bulk-import workbooks), enumerate the render destinations: tables, menus, tooltips, **error messages**, logs. Error-message rendering is an XSS sink with its own escape rules — this wave has a dedicated leg for it (739x).
3. **Management-console metadata battery (lab CROSSBOW or any appliance console).** With one low-priv and one mid-priv lab account: submit marker tokens (quote, backslash, double-hyphen, sleep-timing payloads — no destructive statements) in every free-text field that round-trips: object names, labels, notification condition values, upload filenames, bulk-import workbooks. Log timing/error differentials server-side. Prove scheduled-action and session-control verbs with your own two accounts; prove 403-vs-200 authorization drift per verb. Credential-query legs (89199/89203): prove only *class* (config item readable through an API you weren't scoped for) against synthetic config entries you created; never pull real credentials.
4. **APOGEE/Desigo pre-auth posture (own or explicitly approved building networks only).** Passive first: service inventory (HTTP, FTP) on controller IPs; record version banners. Active memory-read probing is DoS-adjacent on unfixed "All versions" lines — keep to length-boundary probes against lab units, not occupied buildings. The report value is pre-auth reachability + missing-fix status, not crash proof.
5. **Desktop-tool audit for edge-style publishers.** On your own lab workstation: launch the tool, point its backend at an owned listener (self-signed cert) — does it error (good) or proceed (rc9q class)? For xm4q-class renderers, feed the UI synthetic backend data with inert markers via a lab backend; check what the Node bridge exposes (`require` reachability from renderer console). Never against vendor cloud services or shared backends.
6. **UEFI key-database check (owned hardware).** `db` contents readable from firmware setup or via tools like `verify-sig`/`sbsign -i` on extracted BIOS images; flag any test key (Microsoft test keys or vendor test certs) in `db`. Report as boot-chain advisory finding with the key fingerprint.
7. **WinCC DB-role audit (lab).** Enumerate roles granted to the app's DB login (`sysmembers`, server roles); the vulnerable shape is a role carrying xp_cmdshell-class or job-agent rights. Benign canary: prove *role membership*, escalate only in a throwaway install.

## Reporting checklist

- Name the **ingress field → render sink → session-rights chain** exactly: "attacker-controlled comment field in trace CSV → Trace page render → JS executes with the importer's web-server session, which can write PLC values in scope." The scope sentence is the impact; do not overclaim to "unauthenticated PLC RCE."
- For multi-field waves, submit **one finding per ingress field or cite the sibling list** — vendors fixing one field ship eight unfixed (this advisory set is the proof); state which fields you proved.
- For SQLi-on-metadata legs, attach the field path (Bulk Import workbook cell → facility-name query), the parse error/timing evidence, and the privilege tier required — authenticated-with-privileges stays honest severity.
- For credential-disclosure legs, redact values; report "administrative credentials for N internal systems retrievable via query X" with synthetic entries.
- For missing-authz legs, ship the verb × role decision table (admin/minimal × disconnect/schedule/task-state) with 403-vs-200 results.
- For the Secure Boot leg, include the test-key subject/fingerprint from `db` and the bootable proof class (signed test payload on lab hardware only).
- Separate protocol pre-auth DoS from the memory-read leg — only the read is an info-disclosure claim.
