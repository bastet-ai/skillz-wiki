# Brocade Fabric OS SAN management-plane wave: in-band Fibre Channel peer auth bypass, IdP-claim role binding, and header-as-transport trust on the forgotten fabric network

Source: hourly offensive-security scan of GitHub Security Advisories, 2026-10-08 (wave published 2026-10-08T03:31Z, ~18 advisories, CVE-2026-87659 through CVE-2026-87686 plus CVE-2026-94578/94582/94583; fixed band **Fabric OS before 10.0.1**).

One theme ties the batch: **a SAN fabric is a second, unmonitored network with its own in-band management protocol, and Fabric OS treats that protocol — plus client-controlled HTTP fields and IdP-returned claims — as stronger evidence of authority than the transport layer.** Data-center engagements routinely scope the Ethernet management VLAN and never the Fibre Channel fabric; FC switches sit on the same management networks as everything else. Every leg is individually testable in an authorized lab or customer-approved data-center assessment.

## Why this is worth an operator page

- **The fabric is a trusted message bus, and in-band CT is an authentication-free admin channel.** The marquee leg (6h29) means once *any* switch is compromised — or any host with an HBA is footholded — the attacker joins the fabric and speaks vendor-unique Common Transport admin requests to every other switch with no credentials: reset admin passwords, reboot, **push firmware**. Data-center engagement rule: ask whether FC switches / SAN zones are in scope; if a host with an HBA is in scope, the fabric is reachable in fact. Fingerprint with `sclt`, `finddev`, `fabricShow` equivalents from a footholded HBA host; validate only in labs or customer-approved SAN windows — firmware-download legs are destructive on production fabrics.
- **IdP-returned attributes are authorization inputs, not just identity inputs.** The AAA leg (6chm) is the appliance flavor of the [Sept 16 IdP-authority page](2026-09-16-zitadel-keycloak-nezha-identity-provider-authority-boundaries-ghsa.md): the RADIUS VSA / LDAP claim that *selects your admin role* comes from a server the appliance merely trusts at session-establishment time. Audit any appliance with RADIUS/TACACS+/LDAP/federated login: capture the Access-Accept/claim set a real admin session receives, then test replaying or crafting those attributes from an identity provider you control (disposable tenant, fake RADIUS with `freeradius` in a lab). Vendor role-attribute names are frequently guessable from docs — the check "does the appliance validate *which* IdP sent this attribute, or only that an attribute arrived" is the finding.
- **Proprietary-protocol opcode space is wider than the RBAC classifier.** The opcode leg (h7f4) generalizes: with read-only credentials, drive **non-standard/reserved action opcodes** of the management protocol, not just the documented verbs. The classifier maps the verbs the docs name; the executor accepts more. Same shape as the [Oct 6 Coraza cap-semantics lesson](2026-10-06-coraza-waf-evasion-wave-argument-limit-silent-drop-multipart-truncation-and-audit-log-forgery-ghsa.md) — the gate and the worker disagree about input space; here the gate's opcode taxonomy is smaller than the handler's.
- **Two client-controlled-string trust decisions that should have used the socket.** Headers-only internal gating (w843) and `Host`-header-as-transport-trust (3whm) are one sweep: on any appliance web/REST surface, (a) attempt internal/admin endpoint families with guessed internal headers (`X-Forwarded-*`, product-internal names — brute from JS bundles and error text), and (b) move between IP-filtered zones by rewriting `Host` while your socket source stays outside the allowlist. Positive/negative decision table per endpoint. See also the [Sept 15 header/parser-route page](2026-09-15-http4s-ember-traefik-parser-header-route-boundaries-ghsa.md).
- **Logical-switch = tenant, and the scope check was absent.** MAPS dump (f78x) reads chassis-wide data across *all* logical switches with any authenticated low-privilege account — the [Sept 18 ignored-scope page](2026-09-18-ignored-scope-parameters-kcp-identity-header-smuggling-convoy-perses-obot-ghsa.md) tenancy harness applies: enumerate every read endpoint and diff what a scope-limited principal sees vs an admin; any endpoint whose response contains foreign-logical-switch identifiers is a finding.
- **Directory-integration expands the attacker set to the enterprise AD/LDAP forest.** The session-verification cmdi (m36q) explicitly names a *compromised directory service account* as the exploit principal — one phished AD credential becomes OS command execution on storage-network appliances. In red-team scope-mapping, every appliance with LDAP/AD login binding is a pivot from enterprise credential compromise to the storage/SAN plane; note the reverse for reporting: cmdi in the *session-verification path* means the payload rides a username or attribute, fuzz shell metacharacters into every identity field (`;`, `` ` ``, `$()`, space variants) during authenticated-leg testing.
- **Config-import files are a pre-activation injection surface.** The FA issuer leg (2fjw) needs only the ability to *supply* a config file for import — directive injection into the web daemon from an `issuer` string. For any appliance with "import configuration" or "apply IdP metadata/file" flows, treat every string field in the import schema as an injection target into the generated server config; validate in a lab import, never on a production management daemon.
- **Support bundles are standing credential targets.** SupportLink cleartext proxy creds (hrhr) extend the Veeam log-directory rule from the [Oct 7 Veeam page](2026-10-07-veeam-br-cloud-connect-backup-plane-role-and-boundary-wave-ghsa.md): diagnostic/support bundles from network appliances routinely embed proxy URLs, tokens, and config state. On engagements, locate where bundles are stored (shares, TFTP/FTP drop points, support-portal caches) and grep bundles for `://.*:.*@` proxy-credential shapes.
- **Unauthenticated reachables for fingerprinting:** SNMPv3 (default-config overflow surface), **UDP/500 on FCIP extension blades** (a single IKE_INIT-shaped packet hits a parser with no handshake state), and the web management daemon (query-string numeric range crash). If you see FCIP/IPsec-enabled FC switch management IPs on a scoped network, you are looking at unauthenticated memory-corruption surface — report reachability plus version band (< 10.0.1) rather than firing packets at production fabrics.
- **Concurrent-request response crosstalk (gwmc)** is a low-sev but reusable probe: for management endpoints that build responses from a per-request address/context variable, send N concurrent distinct requests from two lab principals and diff response bodies against expected — swapped context = cross-user disclosure primitive.

## Validation boundaries

All legs are appliance-internal; run against lab Fabric OS < 10.0.1 or customer-approved windows. The firmware-download, reboot, and password-reset legs (6h29) and every overflow packet are **destructive-class on production fabrics** — route through owned lab switches. IdP-claim proofs should use disposable identity providers you control; never replay real admin session attributes captured from a live network into another appliance.
