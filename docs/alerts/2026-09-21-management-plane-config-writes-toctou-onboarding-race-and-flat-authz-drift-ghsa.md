## Why it matters for operators

1. **Setup/onboarding endpoints are a standing recon question.** "Has this product been initialized yet?" is remotely answerable (`GET /api/users/onboarding/status` was also anonymous here) and, when the finish handler is TOCTOU-raced, is a first-contact admin-creation primitive. Fingerprint version, probe the status endpoint, then fire N parallel finish requests with distinct payloads; multiple 200s + distinct JWTs is the proof. This is the Keycloak flow-restart and CuteNews media-panel precedent generalized: **the bootstrap affordance is part of the security model.**
2. **Generated-config injection is its own class.** Octavia's rule: when a control-plane API renders user fields into HAProxy/nginx/systemd/iptables files, (a) fuzz every string field for CR/LF and directive-shaped content, (b) find fields where the validator normalizes (percent-encodes, trims, rewrites) but storage keeps the raw value — that delta is the injection, (c) don't stop after one field: the `tls_ciphers` sibling shipped alongside the `redirect_url` fix target unpatched-in-spirit because nobody enumerated the sink's input set.
3. **Remote config-set APIs are RCE with a delay.** ZLMediaKit's two-endpoint chain (write `ffmpeg.snap` → invoke `getSnap`) shows why "it only changes settings" is the wrong severity frame: sweep every `set*Config`/`updateOption`/`saveSettings` route on media servers, proxies, and panel software, and diff which parameters later reach shell, file, or path sinks. Grep the source for parameter consumers, not just the setter's auth check.
4. **Session invalidation is a per-transport property.** The Airflow logout-revokes-only-`_token` finding (same day, sibling page) and x-ui's signed-cookie panel are the same audit question asked of each credential transport: after password change / logout / role strip, **replay the old credential on every transport** (cookie, bearer, API key, gRPC metadata) and record which ones survive. A signed-but-self-contained cookie with no server-side session version can never be revoked by design.
5. **Low-role users who can edit config templates control exposure.** Any panel field that lands in a generated listen/bind/restart path lets an untrusted role move services onto public interfaces. When enumerating a management panel, diff what *each* role can change in settings, then restart/reload and re-scan listening sockets from an external vantage.
6. **One shared service layer = one authz drift per endpoint, by default.** The jshERP cluster is the clearest single-product exemplar of the route-family authz sweep we keep citing: enumerate the CRUD family, then for each verb test (a) privilege to perform the action, (b) ownership of the target object, (c) tenant scope, (d) what the *response* returns. A generic `updateOneValueByKeyIdAndType` that dispatches on a caller-supplied `type` is remote state-dispatch — every accepted `type` value inherits every missing check.

## Replayable validation boundaries (authorized labs / owned instances only)

1. Race proof: lab instance reset to pre-onboarding state; fire ≤10 parallel finish requests with distinct synthetic users; record status codes + returned JWTs; delete created users immediately. On production: dispatch/evidence only (status endpoint + 403-vs-200 verdict) — never create accounts.
2. Config-injection proof: private OpenStack lab project only; inject a **comment-line** marker (`# canary`) rather than an active directive, then read the rendered HAProxy config from the amphora (approved lab access) to prove the raw byte survived the validator→sink leg. Never inject working directives on a shared proxy.
3. Config-write proof: disposable ZLMediaKit in a container; set `ffmpeg.snap` to a marker command that writes a temp file, invoke `getSnap`, observe the file, remove config. Never against reachable streaming infrastructure.
4. Cookie-replay proof: your own lab admin account; capture the session cookie, rotate the password from a second session, replay the old cookie; record survival. Never hold a real user's cookie across rotation.
5. jshERP-class sweep: two lab tenants × two role tiers; canary rows per tenant; for each endpoint run the four-question matrix (privilege/ownership/tenant/response-content). Password-hash disclosure proof stops at "field present, value redacted in report" — never crack or replay real digests.

## September 22 follow-up: an `/anyone/` route family is a flat-authz confession (lamp-cloud 5-GHSA cluster)

- **lamp-cloud ≤5.10.0** shipped five authorization-drift GHSAs concentrated on endpoints mounted under the `/anyone/` prefix — a naming convention that already telegraphs "identity never checked here": `PUT /anyone/baseInfo` + `PUT /anyone/avatar` rewrite **any** user's profile from caller-supplied target IDs ([CVE-2026-94534](https://github.com/advisories/GHSA-fp33-7f49-fwpm)); `getUserInfoById` iterates `userId` to harvest mobile, email, **national ID card numbers**, WeChat/DingTalk OpenIDs ([CVE-2026-94532](https://github.com/advisories/GHSA-v92q-v83r-rr2p)); `FileAnyoneController` `/anyone/file/down|download` serves any attachment, ownership `created_by` column never consulted ([CVE-2026-94533](https://github.com/advisories/GHSA-75cj-c67p-vvgx)); `/anyone/extendNotice/deleteMyNotice` deletes other users' notices by ID ([CVE-2026-94535](https://github.com/advisories/GHSA-ch7p-78m2-fq4j)); `/anyone/visible/resource` enumerates any employee's role codes, permission codes, and full front-end router tree via `employeeId` ([CVE-2026-94536](https://github.com/advisories/GHSA-gvmp-m7fp-qm34)).
- Operator rules: (1) **route-prefix naming as recon oracle** — grep docs/OpenAPI for prefixes like `/anyone`, `/public`, `/open`, `/common`; controllers under them are the highest-yield authz-drift population, test each with a *different* user's object IDs. (2) The router-tree/permission-code enumeration (`/anyone/visible/resource`) is a **pre-attack target map**: it hands you the role model and the exact front-end routes before you exploit any of them — same value as the jshERP `type=UserRole` ladder map, and PII harvest (national ID numbers) makes even the read-only legs reportable at high severity. (3) File-download legs that ignore their own `created_by` column are the classic jshERP by-id CRUD twin — run the four-question matrix (privilege/ownership/tenant/response-content) per endpoint.
