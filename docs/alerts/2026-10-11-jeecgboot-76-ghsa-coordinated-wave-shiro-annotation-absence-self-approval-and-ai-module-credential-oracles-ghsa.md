# JeecgBoot coordinated wave (76 GHSAs): annotation-absence as the authz model, self-approval workflows, and an AI module full of credential oracles

**Wave in one line:** Seventy-six advisories against JeecgBoot ≤3.9.5 (Java low-code platform, Spring Boot + Apache Shiro) published in one batch at **2026-10-11T00:30Z** — almost every one is a handler that simply **lacks the `@RequiresPermissions` annotation its siblings carry**, which makes annotation-absence the authorization boundary for the whole product class: any authenticated session reaches every un-annotated route, including DB-credential, MCP-token, tenant-ownership, and audit-log-wipe endpoints.

**Signal:** 76 GHSAs (7 high, 69 medium, CVE-2026-108605–108680), all `through 3.9.5`. Representative legs below; the full set is the sweep lesson itself. JeecgBoot ships a large `/sys/**` + `/airag/**` + `/openapi/**` management surface out of the box and is common in the wild as internally-built business apps — a high-yield bug-bounty and engagement target.

!!! warning "Authorized validation only"
    Disposable instance, throwaway low-privileged user, synthetic rows/tenants, recorder/rollback for every mutation. Never enumerate a third-party instance, read real DB credentials, or delete audit tables outside an approved lab.

## Why this is durable operator value

1. **Annotation-absence means annotation-presence is the entire allow-list — enumerate handlers, not roles.** Shiro's `@RequiresPermissions` is opt-in per method: a missing annotation is not "deny by default," it is **reachable by every session**. The sweep for any Spring/Shiro app: list controller methods (actuator mappings, swagger export, or source), diff annotated vs un-annotated, and treat every un-annotated one as an authenticated-user endpoint until proven otherwise. JeecgBoot's `SystemApiController` shows the sharpest shape of this: an **internal aggregation API** (`/sys/api/*`) built for trusted server-side callers, exposed on the same public port with the same session filter — the "API for the frontend/internal relay" family deserves its own route dump on every Java app you test.
2. **Pairwise gate parity: every id-consuming verb has an id-source route; gate both.** Twenty-plus legs here follow one template: `DELETE /x/delete` is annotated, `GET /x/list` is not, so the gate protects nothing. Audit rule: for every mutation route, find where its ids come from (list, queryById, export) and require the same minimum privilege on both. This is the Oct 10 HaiND sibling-gate-diff rule (Octop `/api/providers` vs `/api/admin/providers`) generalized to id-supply routes.
3. **Workflow routes are authorization state machines — test requester==approver.** The `doApplyTenantPackUser → passApply` self-approval and the owner-unchecked `changeOwenUserTenant` transfer are the two generic probes for any approval/transfer/invite feature: (a) can the principal who creates a request also satisfy it? (b) does the transfer endpoint verify the caller holds the thing being transferred? Also grep for the misspelled-handler class: typo'd route names (`changeOwenUserTenant`, `Owen` for `Owner`) mark code paths that skipped naming review — fuzz bundles for common misspellings.
4. **App-served crypto keys defeat app-served encryption.** `/sys/getEncryptedString` exists to make logins look encrypted; the same key decrypts password ciphertexts returned by an unguarded route. For any app with a key/init/bootstrap endpoint (login encrypt keys, RSA pairs, signature secrets), assume every other use of that key is confidentiality-zero. Probe: capture the key endpoint, try it against every "protected" response field you can obtain.
5. **Sentinel parameters on bulk verbs.** `ids=allclear` is a sentinel the handler interprets as "everything." Replay-test bulk delete/update endpoints with empty value, `*`, `all`, `allclear`, and framework-flavored sentinels against lab rows — and note audit-log deletion specifically: it changes the cost of noisy testing on any platform you operate against with scope.
6. **The AI sidecar module is the least-reviewed attack surface.** AI/LLM features bolted onto mature CRUD platforms reuse the platform's (broken) authz and add new shared-state classes: per-feature **shared Redis keys** as global prompt stores, MCP/datasource config tables as **outbound-token vaults**, embedding search as **cross-tenant corpus read**, prompt export as **bulk IP/credential harvest**, and generation history keyed by a caller-supplied `userId`. When a platform gains an `airag`-style module, diff its controllers against the core app's annotation coverage first — new module, old bug.
7. **Commented-out checks are live intelligence.** The MCP-config leg's check is `// permission` in the shipped source. For open-source Java apps, `git log -S 'RequiresPermissions'` (comment-out diffs) and grep for commented authz lines finds siblings the advisory wave didn't name. Same-product re-sweep applies: one missing-annotation wave predicts the next.

## Replayable validation boundaries (lab/authorized scope only)

- **Annotation-absence sweep (own JeecgBoot-class lab):** dump route inventory (`/v2/api-docs` swagger export or actuator mappings) with a throwaway low-priv session; request every `/sys/api/*`, `/airag/*`, `/openapi/*` route; table status codes + payload presence. Evidence = route→privilege matrix. Never run this against a third-party host without written scope.
- **Id-source parity probe (lab rows):** for one resource family, confirm list returns ids the gated mutation consumes, with the lowest-tier token. Marker rows only; record field names, not values.
- **Self-approval decision table (two disposable tenants):** apply → approve as same principal → assert privilege delta (tenant-admin pack granted). Revert after capture.
- **Key-endpoint decryption check (lab user set):** fetch `/sys/getEncryptedString`, request your **own** user's record via the unguarded read, decrypt locally to prove the wrap. Never target another real user's material outside the lab.
- **Sentinel bulk-verb test (scratch rows only):** bulk-delete one scratch row, then `ids=allclear` against a **seeded scratch table in an isolated schema**, with audit export first. Never point this at `sys_log` of a shared instance.
- **Shared-key prompt poisoning (lab Redis):** snapshot the `airag:ocr`-style key, write a marker template via the user route, observe another lab user's call consuming it, restore. Never touch production caches.
