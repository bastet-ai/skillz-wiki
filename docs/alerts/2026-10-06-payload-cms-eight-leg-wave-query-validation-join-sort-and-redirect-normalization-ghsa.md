## Why one product's wave is an operator map

The fifteen legs share one architecture: Payload's generic find API takes user-controlled `where` (Mongo-style operators), `sort`, and `joins`, a query-validation layer is supposed to enforce per-field access *before* the database adapter builds SQL, and a field-ACL pipeline is supposed to guard every read/write verb. Every one of the read-side legs is the same failure with a different miss:

1. **Grammar-key case sensitivity in the validator** (`AND` ≠ `and`). The validator whitelists structural keys by exact string; the DB adapter's query builder treats them case-insensitively (SQL is). Anything the validator doesn't recognize is not rejected — historically it was *skipped*. Durable probe on any Mongo-grammar-over-SQL surface: `{"AND":[...]}`, `{"Or":[...]}`, `{"and ":...}` — if a filter that should fail path-validation succeeds, the validator and the executor disagree on the grammar. This is the Sept 18 query-grammar family's newest axis: not operator injection, **structural-key normalization differential**.
2. **Validation coverage is per-parameter-plane, not per-query**: `where` validated, join-internal `sort` not. The fix file `validateSortQuery.ts` (83 new lines) did not exist before — sort fields simply never entered the field-access model inside joins. Sweep rule: for every query parameter plane a framework accepts (`where`, `sort`, `limit`, `joins`, `depth`, `draft`, `locale`, version params), ask which ones pass through field-level access validation; default assumption is the *least-documented* plane is unvalidated. Sorting by a protected column is an oracle: order results by the secret field, binary-search its value through rank observation — and Payload's join leg shows the same oracle reaching password-reset tokens (pair with the Sept 18 ClickHouse filter-key and MyBatis-Plus `concatOrderBy` legs on the [Sept 18 query-grammar page](2026-09-18-mongoid-orm-query-grammar-blazar-authz-fallback-and-cotonti-predictable-tokens-ghsa.md)).
3. **Join filters as an inference channel even without SQLi**: polymorphic joins (`join.on` referencing sensitive collections) let a permitted query *ask yes/no questions about read-restricted fields* on the joined document. Field-level ACL protects GET output, not predicate participation. Operator test: any collection with a join to users/credentials — try `where[joinField.secretField][equals]=guess` and diff result counts; then sweep `greaterThan`/`contains` for progressive extraction. This is the presence-oracle class generalized to *predicate* position.
4. **Redirect validation must normalize like the browser**: `/\t//example.invalid` — browsers strip tab/CR/LF from URLs, so `/%09/%2f`-prefixed "local paths" become protocol-relative. Payload's test additions enumerate the exact battery now worth keeping in any redirect harness: `%09 %0D %0A` single-encoded after a leading `/`, plus `%25`09 double-encoding, `%255C`, `%252f`. Double-encoded whitespace is the part most `startswith('/')`+decode-once validators still miss.
5. **Field ACL lives in the read verb only — enumerate the *other* verbs that return document data.** The second wave (16:17–16:22Z) is one rule stated four ways: the same user document that filters fields on `GET /api/users/:id` came back **unfiltered from token-refresh and password-reset responses** (xgv3), **copied wholesale by the duplicate operation** (vc4h, critical), **plaintext-embedded its own API key in any ordinary read** because the base auth field never got a read rule (238x), and **had its `password` consumed before the field-access pass ever ran** because the auth op special-cased it early (fx49). Sweep rule: for any field-level ACL claim, list every endpoint whose response body or side effect embeds the document (auth flows, exports, duplicates, versions, webhooks, previews, bulk ops) and re-read the restricted field through each. This is the same sibling-route inversion as the Sept 19 WP alternate-surface page, now with server-side ORM proof.
6. **"Disabled" settings must be verified at the router, not the config.** The critical duplicate leg's true miss was ordering: `disableDuplicate` was assigned during sanitize *after* the default endpoint array was already pushed, so the duplicate REST route existed on every collection regardless. Fingerprint rule: probe the disabled-by-default route family directly (`POST` with `duplicateFrom`-style params) instead of trusting the config default; a feature-flag setting that only gates UI polish still leaves the REST surface. Same shape as Keycloak's disabled-feature-flag alternate routes and OpenAM's legacy `/jaxrpc/*`.
7. **Session tokens must be bound to their collection/audience.** The refresh fix added a check that simply did not exist: `req.user.collection !== collectionConfig.slug → 403`. On any multi-auth-surface app (users + admins + partner portals), replay a token minted for collection A against collection B's refresh/me/logout family — cross-family token acceptance is a standing probe, sibling of the Oct 3 OpenAM cross-realm `_queryFilter` leg.
8. **Has-many relationship filters are independent-constraint oracles.** The 94059cf comment is the cleanest statement of the class: when the caller's filter and the access constraint are AND-ed *loosely* across a has-many relationship, any one readable related document can satisfy one half while a hidden one satisfies the other — you infer properties of documents you cannot read by watching whether the readable row "masks" the query. Related-document pairing of the join-predicate oracle in item 3. Also note the `isNestedRelationshipQuery` prototype-identity check: distinguishing "plain object = sub-query" from class instances (ObjectId) by `Object.getPrototypeOf` is the fix shape — pre-fix, the parse itself was type-ambiguous.
9. **Payment confirmations are state machines; replay them.** The ecommerce leg shows a confirm endpoint without an atomic pending→processing claim = replayable multi-settle (repeat order creation/cart purchase/inventory decrement). Durable check on any checkout/credit/wallet flow: fire the confirmation twice concurrently with the same transaction reference and diff side effects (second order? double inventory decrement? double grant?). Idempotency-key absence is fingerprintable before you even have a payment method.

## Plugin-surface rule

Four of the fifteen legs are **plugins** (stripe, mcp, import-export, ecommerce), all disabled in default installs. Payload's own impact statement leads with "Applications that do not use X are not affected" — which inverts into the fingerprinting rule: **on a Payload target, enumerate enabled plugins first** (`/api/plugin-import-export/*`, Stripe proxy routes, MCP key endpoints, ecommerce checkout/confirm routes exist only when mounted) before spending time on core. The unauthenticated-RCE leg needs only the import-export plugin enabled — one optional dependency turns a clean install into an unauth attack surface. Same lesson as the June 19 Langflow connector loop: plugin inventory is the first recon phase on plugin-based CMSes.

## Validation workflow (authorized scope only)

1. **Fingerprint adapter**: request a `where` on a json/richText field and compare Postgres/SQLite vs Mongo error shapes; the SQLi leg is Drizzle-only. Version-fingerprint per-advisory: patched bands are 3.88.0 (SQLi, import-export, sort, redirect) and 3.90.0 (join disclosure, Stripe proxy, PBKDF2, and the entire 16:17–16:22Z auth wave: API-key disclosure, duplicate bypass, refresh/reset field leak, relationship oracle, password-update access, ecommerce replay, multipart bounds) — a target can sit between the two bands and still leak reset tokens.
2. **Grammar-differential probe**: submit a filter with `{"AND":[{"secret.path":{"equals":"x"}}]}` vs the lowercase form. Expect identical 400-path-validation from ≥3.88, and on vulnerable builds a behavior difference (200 vs 400, or results vs QueryError) proving the structural key escaped validation. Synthetic paths only; never probe real credential fields beyond your own canary collection.
3. **Sort oracle**: with a disposable low-priv account that can query one readable collection, set `sort=<protectedField>` (and the same inside each join's `sort` param). A 200 + deterministically-ordered results where field read returns 403 is the finding. Binary-search ranking only against synthetic values you planted yourself.
4. **Join predicate oracle**: for each discovered join, run one `equals` guess against a joined sensitive field you planted (canary reset token), record count>0 vs count=0. Prove inference, do not exfiltrate real tokens; report the count-differential artifact.
5. **Redirect battery**: replay the fix-commit test vector list (tab/CR/LF + double-encoded `//` prefixes) against every `redirect=` parameter in auth flows, including GraphQL login mutations; verify against `Location` headers with a URL parser that strips whitespace the way browsers do.
6. **Plugin enumeration**: unauthenticated requests to import-export preview/export endpoints, the Stripe proxy path, and MCP key CRUD — decision table (route status + response shape) per plugin, with and without a lowest-tier account, plus the cross-account MCP key check using two disposable users (never live keys).
7. **Multipart ReDoS check** (import-export only): a `Content-Type: multipart/form-data; boundary=;;;;...!` with ~50 semicolons should return a fast 4xx on patched builds; multi-second response on the gate = pre-fix regex; run once against your own lab instance only (availability impact). Companion check on core uploads: an oversized upload that returns 2xx with a silently truncated file = pre-`0084bd5` `abortOnLimit:false` default — prove against your own canary file hash mismatch, not a real asset.
8. **Auth-response field sweep**: with a disposable pair of accounts (one can read the other's document if the config allows), call `POST /api/users/refresh` and the forgot/reset flow with an **expired-but-parseable** JWT and record which fields appear in the returned user object vs the same user's filtered read response. Restricted/hidden fields present in refresh/reset bodies = CVE-2026-105853 shape. Redact everything but field names in evidence.
9. **Duplicate-verb probe**: with the lowest-tier account, attempt the duplicate operation (`duplicateFrom`-style param on the create route) against a document containing a field your role should not read (self-planted canary). A created copy carrying the canary value proves the ACL-free copy path regardless of `disableDuplicate`. Auth collections default this off at ≥3.90 — a 400 "cannot be duplicated" on the *route* (not a field filter) is the patched fingerprint.
10. **Cross-collection token replay**: mint a token on auth collection A, then call collection B's `refresh`/`me`/logout family with it. Acceptance (200 + B-scoped identity) = missing collection binding (CVE-2026-105853's sibling check). Two disposable auth collections in your own lab instance.
11. **API-key-in-read check** (auth collections only): with account A reading account B's user document (where config permits), diff for `apiKey`/`apiKeyIndex` fields in the response body. Present = pre-fix base-field config; report only field presence against your own seeded key, then rotate it. Never retain another account's live key in evidence.
12. **Confirm-replay check** (ecommerce plugin only, authorized lab): fire the Stripe order-confirmation leg twice concurrently with the same transaction reference and diff side effects — second order row, second inventory decrement, or double cart-purchase flag = missing atomic claim. Lab store with synthetic products only; never against live payment credentials.

## Reporting checklist

- Label adapter + plugin state per target; the same Payload version is four different attack surfaces depending on DB adapter and enabled plugins.
- Separate the claims: sort-disclosure (ordering side-channel) ≠ join-predicate inference (yes/no oracle) ≠ SQLi (adapter-level). Each needs its own evidence artifact; do not bundle as "API access control bypass".
- For reset-token inference, prove with a token you generated and redact the value; report only the count-differential trace.
- Cite the fix commit alongside each leg — the `toLowerCase` and array-rejection hunks are the proof that `AND`/array-constraint filters previously bypassed path validation.
