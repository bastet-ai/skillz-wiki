# Request-derived identity, injected-guard composition, and a blind-SSRF status oracle (Sept 17 14:48–14:59Z wave)

Source: hourly offensive-security scan of GitHub Security Advisories, 2026-09-17 (wave published 2026-09-17T14:48Z–14:59Z).

One theme ties the durable records: **the security decision reads its own scope parameter, or its own composition operator, from the request.** Tina takes the identity issuer from the query string, Vendure composes its injected visibility guard with the caller's chosen `filterOperator`, and Marten interpolates the filter *key* (not just the value) into SQL. Nuxt OG Image adds a reusable blind-SSRF measurement trick.

## Why this is worth an operator page

- **The request-derived scope parameter is the identity equivalent of a Host-header trust.** `isAuthorized` answers "is this a valid user of whatever app the caller names?" instead of "…of THIS site." Audit rule: on any SaaS-to-self-hosted auth relay, send your **own** app/tenant/client identifier (freely registrable on the IdP) with your own valid token and record whether the victim site accepts. The same issuance-provenance axis as the Sept 17 WordPress QR-login and feed-key items — validation of *existence* where what matters is *provenance*.
- **Injected authorization guards must be AND-composed, never operator-composed with caller input.** `filterOperator: OR` is a public, unauthenticated parameter on the Vendure Shop API; the same shape shows up in any GraphQL/list API that lets clients pick AND/OR over filters that include a server-injected predicate. Probe: add a predicate that matches a hidden entity, flip the operator, compare result sets against a negative control with the operator absent.
- **Dictionary/EAV filter keys are injection surfaces that value-focused fuzzing misses.** Bug-bounty angle: wherever an API filter passes a user string as a *key* (`attributes[<user>]`, tag/label/field selectors, `ContainsKey`), send a single quote before sending payloads in the value position; the key leg reaches SQL string-literal assembly on the Marten class of ORM.
- **`innerHTML` → `textContent` is a fake sanitizer.** Any React/Vue "strip HTML for preview cell" that round-trips through a detached element executes `onerror`-style handlers during parse. Treat every admin-panel list cell rendering stored rich-text fields as a stored-XSS candidate; prove with an image-request or marker-event canary, never cookie fetch.
- **The Nuxt OG Image status oracle is a generic blind-SSRF measurement pattern.** Where an SSRF response is consumed opaquely (fonts, images, parsers), differential outer status codes (fail-vs-target-2xx) are frequently still emitted; harvest the oracle before concluding "blind". It supports port liveness and IMDSv1 credential-issuance detection without reading a byte of response body.

## Validation workflow (authorized scope only)

!!! warning "Disposable identities and owned callbacks only"
    Use throwaway accounts, apps, and tenants on every leg. Never link real accounts, never read real customer catalogs, media buckets, or tenant rows, never hit metadata endpoints outside an explicitly authorized target.

1. **Tina-class auth relay:** with two disposable TinaCloud (or analogous IdP) apps, authenticate app A normally, then replay token A against the victim self-hosted site with `?clientID=<app-A>`. Evidence: 200 + accepted `authorized` verdict and a benign media-list or content-query call; do not upload/delete against a real bucket.
2. **Guard-composition probe:** in a disposable storefront, disable one product, mark one collection private, then query the public Shop API with a predicate matching the hidden entity under `filterOperator: OR` and without it. Evidence: presence-only rows/fields in the decision table.
3. **External-auth ATO:** two lab accounts; configure a mock OAuth strategy that returns an unverified victim-lab email; confirm link-to-existing vs create-new behavior at the service boundary. Provider must be lab-controlled; never use real social providers.
4. **Detached-node XSS canary:** in an authorized lab dashboard, set a product description to an `<img>` whose `onerror` fires a fetch to an owned no-content callback; evidence is the single callback hit.
5. **ORM key-position SQLi:** against an owned Marten-backed app only, request a filtered route with `key = "nonexistent' = '' or 1=1 --"` and confirm row-scope change or distinct error; use a read-only DB role; never send statement separators against a live multi-statement connection.
6. **Blind-SSRF oracle:** point `fonts[].path` at owned redirectors/callbacks only — one returning 200, one returning 404 — record the outer status mapping, then stop. Metadata/LAN enumeration applies only where that scope is explicitly authorized, and capture reachability booleans, never credentials.

Reporting heuristic: title by the broken binding — **auth verdict scoped by caller-supplied app id**, **visibility guard OR-composed with caller filter**, **dictionary filter key to SQL literal**, **SSRF response discarded but status leaked** — and include the positive/negative decision table plus patched-version behavior.

## September 20 follow-up: Argo Workflows NotEquals field selector drops the cluster-scoped access review

[GHSA-3fwg-9p8x-37mv](https://github.com/advisories/GHSA-3fwg-9p8x-37mv) / [CVE-2026-93991](https://nvd.nist.gov/vuln/detail/CVE-2026-93991) (7.7, Argo Workflows 4.1.0–4.1.3): `ListArchivedWorkflows` fails to apply the cluster-scoped access review when the `metadata.namespace` field selector uses the **NotEquals** operator. A caller with only namespace-scoped list permissions sends `metadata.namespace!=<own-namespace>` (or iterates the negation) and retrieves archived workflows from **all other namespaces** — exposing spec arguments, parameter values, and annotations.

Operator value: this is guard-composition drift reached through **operator polarity** rather than AND/OR. The authorization branch keys on recognizing a *positive* namespace selector to trigger the broader access review; the negated selector form falls through a code path that never triggers the review. Audit rule: for any API where a caller-selectable filter operator (Equals/NotEquals/In/NotIn/contains) intersects a server-injected scope predicate, enumerate the **full operator matrix** — including negations and the operator-absent case — and diff the returned-scope set per cell. A scope check proven on `=` says nothing about `!=`; the negative form is precisely the one that describes "everything except my scope." On Kubernetes-adjacent surfaces, also sweep field-selector and label-selector parser surfaces for operator spellings (`=`, `==`, `!=`, `~`, `!~`, set-based) that take different authorization branches. Validation: two disposable namespaces with synthetic archived workflows carrying marker parameters, one low-privilege namespace-scoped ServiceAccount; capture the operator-vs-visible-namespaces decision table on affected and fixed versions; never read real workflow payloads.
