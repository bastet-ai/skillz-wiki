# Media-pipeline edge surfaces: filename shell-out, metadata XML XXE, author-template RCE, and chunked-upload validation asymmetry

Source: hourly offensive-security scan of GitHub Security Advisories, 2026-09-20 (wave published 2026-09-20T12:30Z).

Advisories: [GHSA-7c6f-jc48-6hfq](https://github.com/advisories/GHSA-7c6f-jc48-6hfq) / [CVE-2026-94106](https://nvd.nist.gov/vuln/detail/CVE-2026-94106) and [GHSA-gmhw-pxmg-j22w](https://github.com/advisories/GHSA-gmhw-pxmg-j22w) / [CVE-2026-94108](https://nvd.nist.gov/vuln/detail/CVE-2026-94108) (getID3), [GHSA-w599-5qgp-f3cf](https://github.com/advisories/GHSA-w599-5qgp-f3cf) / [CVE-2026-94109](https://nvd.nist.gov/vuln/detail/CVE-2026-94109) (openEQUELLA), [GHSA-m76p-p4wh-76x9](https://github.com/advisories/GHSA-m76p-p4wh-76x9) / [CVE-2026-94104](https://nvd.nist.gov/vuln/detail/CVE-2026-94104) (NivoCart).

Four records from one wave generalize into the same hunting rule: **the media/upload pipeline has more code paths than the upload endpoint** — filenames get interpolated into shell commands, metadata sidecars get XML-parsed, "personalization" fields get compiled by a template engine, and the chunked-upload branch skips the checks the single-file branch runs. Each is a separate sink reachable from the same "benign" file-upload or content-edit feature.

## Why this is worth an operator page

- **The filename is an injection site when any handler shells out.** Everyone fuzzes file *contents*; almost nobody fuzzes the *name* against media pipelines. Any app that probes uploads with an external binary (getID3's shell-out handlers, ffmpeg/ffprobe wrappers, ImageMagick delegate calls, `exiftool` glue) may build `cmd <name>` strings. Upload canary names shaped like `'$(id).mp3`, `x;touch /tmp/;1.mp3`, backtick and `|` variants (URL-encoded and raw, multipart filename and stored path) and diff probe-side effects against a plain name. On open-source PHP stacks the grep is two-step: `getID3` in `composer.json`, then any user-controlled path reaching `exec|shell_exec|system|passthru|proc_open|popen`.
- **Metadata sidecars are a hidden XML entry point.** The XXE battery normally runs against SOAP/API endpoints; CVE-2026-94108 shows the same primitive reachable by embedding XML in a media container that a *metadata parser* XML-parses. On every upload feature, ask: which parsers see which parts of my file (containers, sidecars, EXIF/XMP, ID3 XML tags, zip comment blocks)? Craft a media file whose metadata block is an XXE canary (inert out-of-band marker against an owned callback) and watch whether the parse error or fetched resource leaks. `simplexml_load_*` without `LIBXML_NOENT`-disabling discipline, `XML2array`-style helpers, and any PHP < 8.0 host are the fingerprint.
- **"Personalization" fields are template-engine entry points.** LMS/CMS/repository platforms that let authors write collection summaries, dashboard portlets, or email/MIME templates frequently back those fields with FreeMarker/Velocity/Twig with the *default* class resolver. Test each free-text authoring field with the canonical inert FreeMarker probe (`${"freemarker.template.utility.Execute"?new()("id")}` equivalent kept lab-only and marker-only, e.g. `?new()` on a class that only prints a constant or writes a marker file) and record which fields get *compiled* vs stored. Same rule as the Sept 19 hono/jsx and OpenPanel items: **the sandbox policy belongs to the render/compile path, not the product** — unsandboxed resolver means the field is RCE for the lowest role that can edit it.
- **Run every validation matrix branch, not just the default one.** NivoCart's chunked branch skipped the extension check the single-file branch enforced — the `chunks`/`chunkNumber`/`resumable` parameter family (tus, resumable.js, plupload, dropzone servers) is a validation-bypass class of its own. For any upload endpoint that supports chunking: upload the *same* disallowed-extension file once as a single request and once as a multi-chunk sequence, and also under an alternate filename, then diff verdicts. This is the validate-leg ≠ persist-leg family with a **parameter-selected code path** twist.

## Validation workflow (authorized scope only)

!!! warning "Inert markers, lab targets, no live shells"
    Prove command execution with marker-file/marker-output techniques on lab installs you own; never deploy web shells or touch production media libraries. XXE proofs use owned callbacks only. Template probes print constants — no downloaders, no reverse shells.

1. **Filename canary matrix (media upload, lab).** Same tiny valid media bytes under N names: plain, `$(marker).ext`, backtick, `;touch-marker`, `|`, percent-encoded variants. Record: accepted/stored name, probe-side effects (latency, marker file), and whether the *stored* path re-enters a probe/shell-out call later (rename-then-trigger chains).
2. **Metadata XXE canary.** Build a valid container (audio/video) with an XML metadata block containing an external-entity reference to your owned no-content callback. Upload; poll callback and error text. Negative controls: entity-disabled parse on PHP ≥ 8.0 and plain metadata file.
3. **Template-field sweep (openEQUELLA-class or any platform with author templates).** Enumerate every free-text field that renders styled output (summaries, portlets, notification email templates). Submit per-engine inert probes (FreeMarker `?new()` on a constant-print class, Velocity `#set` math, Twig `{{7*7}}`) and record which field compiles which engine. RCE claim requires the Execute-class proof **on a lab instance only**, captured as marker output.
4. **Chunk-vs-single upload parity.** Same disallowed-extension file: single POST, two-chunk sequence, three-chunk sequence, alternate filename per leg, plus `chunks=1` vs `chunks=2` parameter-only flip. Verdict table proves the branch asymmetry; place the file in the app's stated upload dir and confirm executability claim by *response of the handler mapping*, not by running commands.
5. **Fingerprint before claiming.** getID3 version from error strings/`composer.lock` echoes; openEQUELLA version from product footer/about API; fixed lines: getID3 1.9.26, openEQUELLA 2026.1.0, NivoCart > 2.4.0 (no fix — "through 2.4.0").

## Reporting checklist

- For filename shell-out: pin the embedding app + getID3 version, the exact multipart filename bytes, and the marker side-effect evidence; state the privileges of the embedding process, not "root".
- For metadata XXE: show the container structure (which box/atom carried the XML), the entity payload, and callback hit with timestamps; note PHP runtime version when inferable.
- For template RCE: minimum author role, exact field, compiled-vs-stored verdict table, and lab-only Execute proof; report as "content-author rights = server code execution through unsandboxed template resolver".
- For chunked upload: the parameter-only-flip decision table is the core exhibit; note the target's handler mapping if claiming PHP execution.
- Generalize in the report body: filename sinks, sidecar parsers, template-backed fields, and chunk branches are **four extra paths through one upload feature** — the upload endpoint's own validation passing is not a negative control.

## September 21 follow-up: format-agnostic image "validation" + attacker suffix + static mapping = stored XSS

- **newbee-mall ≤ 1.0.0 goods-name stored XSS via image-guard bypass** (CVE-2026-94045, [GHSA-92hr-qfch-w4h7](https://github.com/advisories/GHSA-92hr-qfch-w4h7)): the upload "image-only" guard is `ImageIO.read()` — a **format-agnostic read** that returns non-null for a polyglot file (valid PNG header + `<img onerror>` tail), and it is the attacker-controlled suffix plus the `/upload/**` static mapping that turns the accepted upload into persisted XSS rather than a one-shot blob. Operator rule for every upload feature claiming image validation: a decode-success check validates the *prefix*, not the file — build polyglot canaries (magic bytes + inert HTML/JS tail), request the stored URL under both the real and claimed extension, and confirm the server serves your tail bytes with an executable-context Content-Type. The finding class is the **three-leg chain** — validation leg (decode-only), storage leg (suffix preserved), delivery leg (static route) — pass all three as separate evidence fields. Lab-bounded: synthetic polyglot canaries on your own upload target; never leave live event-handler payloads.

## September 23 follow-up: the same product's second RCE leg — a deserialization denylist enforced on the outer stream only

- **openEQUELLA < 2026.1.0 authenticated RCE via `SignedObject`-nested deserialization** (CVE-2026-67615, [GHSA-h2p3-9m67-89gr](https://github.com/advisories/GHSA-h2p3-9m67-89gr), 8.8): the HTTP invoker endpoint at `/invoker/*` pipes serialized input through `PluginAwareObjectInputStream`, which enforces a class-name **denylist** — but nesting a payload inside a `java.security.SignedObject` makes the **inner content** get deserialized by a *separate* `ObjectInputStream` that applies no denylist, reaching a JNDI sink → code execution for any authenticated non-guest user. Same product as this page's FreeMarker SSTI leg: two independent content-to-code channels, one author-rights, one any-user.
- Durable axis: **deny/allow filters on a deserialization entry point enforce only what the filtered stream itself reads.** JDK-standard container classes that perform *secondary* deserialization on their payload — `java.security.SignedObject`, `javax.management.remote.rmi.JRMP_Stub` (equals/hashCode-triggered), MXClean, Rome `SyndicationImpl` — each open an inner stream outside the outer filter's coverage. Sweep rule for every Java deserialization sink with a hardening class: (1) fingerprint the filtering (`ObjectInputFilter`, custom `resolveClass`, `lookahead`-stream) and read *which* stream applies it; (2) test the payload wrapped in each known secondary-deserialization container; (3) prove reachability of the inner stream with a benign resolved-class marker before claiming the JNDI/exec leg. Lab-bounded: owned LDAP/RMI callbacks and inert marker classes only; never chain to live JNDI against production hosts.
- Generalizes the standing "fix coverage drift" family (mcp-atlassian per-tool validators, Skipper auth-branch hooks): here the drift is **per-stream** — the guard is bound to one `ObjectInputStream` instance, and any code path that constructs a fresh one is unguarded.
