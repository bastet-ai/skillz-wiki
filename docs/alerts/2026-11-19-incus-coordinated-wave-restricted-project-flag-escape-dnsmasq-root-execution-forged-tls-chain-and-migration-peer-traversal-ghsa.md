# Incus wave (18 GHSAs): restricted clients reach host root via dnsmasq and forged TLS chains

Source: GitHub Security Advisories published 2026-11-18T21:31Z for [lxc/incus](https://github.com/lxc/incus) (CVE-2026-130768 through CVE-2026-130787, all **before 7.6.0**, one leg 7.3.0+). Eight critical, nine high, one medium. This is the third coordinated Incus wave on this wiki after [June 26 image/backup host boundaries](2026-06-26-incus-image-backup-host-boundaries-ghsa.md) and the August 30 cross-project copy pair on that page, and it keeps firing because the daemon has *three* listener surfaces (REST, `/dev/incus` guest API, migration/S3/NBD side channels) each with its own trust model.

**Wave in one line:** a certificate restricted to one project can mint root on the host by writing `raw.dnsmasq` bridges into a sibling project that lacks `features.*` flags, inject LXC hooks through line breaks in OCI image config, authenticate as any trusted cluster peer by appending its certificate to your own TLS chain, and steal cluster-join tokens and migration websocket secrets out of broadcast event streams.

!!! warning "Disposable lab only"
    Use an isolated Incus host with throwaway projects and marker-only payloads (`id`/`getenforce` output files, temp canary dirs). Several legs here (dnsmasq scripts, LXC hooks, userns escape, NBD socket hijack) are host-root primitives by design: never point them at a shared or production daemon, never read real trust stores, S3 keys, or other tenants' instance data, and never complete a cluster enrollment outside your own lab.

## Why this is durable operator value

The wave maps the whole container control-plane trust model at once, and most legs are *pre-auth-for-the-victim* primitives: the attacker needs only the cheapest tenant role (or a local unprivileged shell), not admin.

1. **Entitlement vs requested-parameter mismatch, twice.** 130784 checks entitlements against the project *string you requested*; 130773 shows the confinement model itself fails against projects that simply **lack `features.*` flags**. Standing rule sharpened: when a platform partitions by a caller-visible selector, test (a) selector spoofing (`?project=`, `target-project`, `source-project`), (b) sibling containers whose *configuration shape* silently opts them out of the partition (missing flags, unset feature keys), and (c) inherited/shared resources that live in both views. Enumerate project/tenant-like objects and diff their flag inventories before hunting for injection; a flag-less sibling is a pre-built beachhead.
2. **Config fields that a root-run helper executes are RCE surfaces.** `raw.dnsmasq` (executed by dnsmasq's dhcp-script as root), `block.create_options` (mkfs argv), and LXC directives injected by **line breaks inside OCI image config values** are all "config generator = template injection" shapes. Audit grep for any daemon field that lands verbatim in generated dnsmasq/LXC/systemd/mkfs input; battery: newline-then-directive payloads in every image-controlled config key (`config.json` values, `oci.entrypoint`, `oci.cwd`), marker commands only.
3. **TLS chain construction is identity assignment.** 130778 means the presented chain is *assembled into* trust rather than *checked against* it: append the known-public server/cluster certificate and you become a trusted peer. For any mTLS or certificate-authority product, the battery is cheap: present (a) your cert + peer's cert appended, (b) peer cert alone, (c) reordered chain, (d) cross-cluster cert, and diff identity resolution. Same family as the Oct 14 NGINX session-forgery lesson: **session/crypto state is an authorization input, test it as one.**
4. **Event streams and operation metadata are secret channels.** Join tokens (130783), migration websocket secrets (130776), and empty-project OVN logs (130777) all leak through *broadcast* paths that no request-level authorization covers. For any daemon with a subscribe/event API, enumerate every event/operation type and diff its payload against what the REST read path authorizes; subscriber access to another user's operation state is a finding even when nothing "readable" is returned. Race angle: websocket secret + in-flight operation = connect-before-peer hijack, schedule probes around your own long operations.
5. **Abstract unix sockets have no filesystem permissions.** `/proc/net/unix` lists them, `chmod` cannot lock them down, and lifecycle is the operation window (130770). Local recon on any hypervisor/container host: enumerate abstract socket names, correlate with running operations, attempt connect during migration/export. Generalizes to any product using `@`-prefixed socket names.
6. **State-machine asymmetry: rebuild is not launch.** 130774's root cause is that user-namespace setup happens on the launch path only, so rebuild-then-start of a never-started container skips it. For every lifecycle pair (create/start, rebuild/migrate, copy/restore), ask which setup step belongs to which transition, and test the uncommon transition *first* on a fresh object. Same invariant as this wiki's copy-source rule from August 30, now on the security-context axis.
7. **Verify-after-decode/allocate again.** S3 bodies fully buffered pre-signature (130781) and decompression of every forwarded payload regardless of config (see the temporal-proxy twins folded on the [Sept 21 Temporal page](2026-09-21-temporal-internal-deputy-subprocess-provider-and-noobaa-presigned-copyobject-ghsa.md)) confirm the pattern: cheap check first (signature, size cap) must precede expensive transform (buffer, decompress), and per-item caps without a per-response total are no cap.
8. **Untrusted migration peers and backup indexes are input sources, not trusted infrastructure.** The offer header volume/snapshot names (130780) and `index.yaml` snapshot entries (130769, 130779) are attacker strings reaching path joins and pointer dereferences. When a protocol has a "peer" role, treat every peer-supplied string as a path/command/fuzz input even though the role implies trust.

## Replayable validation boundaries

Preconditions: disposable Incus 7.5.x host, two projects (`lab` with `features.*` flags, `flagless` sibling without), a restricted certificate pinned to `lab`, a throwaway OCI image you control, and customer/lab approval for import operations. Patched 7.6.0 is the negative control for every leg.

1. **Flag-escape inventory.** As the restricted cert, enumerate `incus project list -s` output for missing `features.*` keys, then attempt one create (`network create ... raw.dnsmasq=` with an inert `dhcp-script=/bin/true`-class marker) targeting `flagless`/`default`. Evidence: expected denial vs observed create, project flag table before/after. Stop at listing the created object; never run a real dhcp-script against production.
2. **OCI newline canary.** Build a minimal image whose `config.json` label or `oci.entrypoint` value embeds a newline plus `lxc.hook.mount = /bin/true`-class inert directive; launch under the restricted project; confirm via `incus config show` whether the directive reached the generated LXC config. Marker only; do not mount host paths.
3. **Chain-append probe.** Against your own cluster, append the server certificate to a low-trust client chain and record whether the daemon resolves the trusted identity (expected denial on 7.6.0). Also attempt operation-cancel by UUID from an unrelated restricted client.
4. **Event-stream secret audit.** Subscribe as the restricted cert (`incus event listen`), trigger an instance migration in another accessible project, and diff captured operation metadata for join tokens or websocket URLs. This is a read-side check only: capture that the secret *appears*, never use it to complete enrollment outside your own lab.
5. **Abstract socket recon.** During a lab VM migration, read `/proc/net/unix` and confirm NBD socket name predictability; local unprivileged connect is the finding. Never attempt this against a shared host.
6. **Lifecycle asymmetry.** Create an unprivileged container, never start it, rebuild it with an alternate image, start, and compare `id`/`capsh --print` output inside (host uid 0 + capabilities = positive). Disposable container, marker output only.

## Reporting notes

Lead with the specific boundary: "restricted project to host root via `raw.dnsmasq` dhcp-script", "TLS chain append authenticates as trusted cluster peer", "join token captured from default-project event stream". Include Incus version, project flag inventory, restricted-cert entitlement list, storage backend, storage pool names, event subscription scope, and the patched-version negative control. Keep all payloads inert; do not publish working dhcp-script or LXC-hook payloads, do not read real trust stores or S3 keys, and keep NBD/migration hijacks inside the lab window.
