# Wheels (CFML) coordinated eight-GHSA wave: key-finders replace scope predicates, client-selectable test contexts, Host-poisoned boot config, and CLI/MCP injection

Source: hourly offensive-security scan of GitHub Security Advisories, 2026-10-16 (wave published 2026-10-16T06:30:24Z). Second Wheels wave in 24 hours — the Oct 15 quote-reparse SQLi leg lives on the [Sept 18 query-grammar page](2026-09-18-mongoid-orm-query-grammar-blazar-authz-fallback-and-cotonti-predictable-tokens-ghsa.md); same-product re-sweep rule fired again, and this dump is the framework's own authorization/context/config-boundary inventory.

The recurring shape: **framework convenience layers silently drop, widen, or re-select the enforcement decision the application thought it made.** A `findByKey()` convenience finder *replaces* the app's scope predicate with a primary-key condition; a header or cookie switches the request into a *parallel application context* that carries its own rate-limit counters; the `Host` header of the *first request that boots the app* becomes a persisted production setting; nested-form children are resolved by posted key with no parent binding.

## Why this is worth an operator page

- **"Key" finders are the scope-blind door of every ORM/framework.** The scope-replacement leg generalizes far than CFML: any `findById`/`getByKey`-style convenience API that takes a key and *returns a row* must intersect, not replace, the caller's authorization scope — contrast the scope-aware finders in the same framework the advisory says were unaffected. Audit rule: enumerate every finder/aggregate whose name pattern implies direct key access, and diff its predicate handling against the query-builder path the app's authorization depends on. Second durable leaf: **`exists()` returning `true` on out-of-scope keys turns an authz bug into a standing enumeration oracle** even when errors are suppressed — test exists/read/update/delete separately for the same foreign key; they routinely disagree.
- **Client-selectable application context = a parallel enforcement plane.** The `X-Wheels-Test-Context` leg is the header/cookie-selected-route-family family (nginx-ui MCP mount, Keycloak versioned account routes) at *application-instance* granularity: the alternate context keeps config, datasource, and debug settings but resets **in-memory state** — so per-context rate-limit counters and maintenance-mode flags silently fork. Hunt rule: on any framework, grep for context/env/tenant selectors read from headers, cookies, or URL substrings (note: the trigger is a path substring **anywhere in the URL, including the query string** — sweep param values for internal route names), then re-run your limiter and maintenance-mode probes through the alternate context; counters that "hit the limit" on the normal path may be brand new behind the selector.
- **Boot-time derivation turns one request into persistent config.** Host-header-as-error-recipient is Host-as-data again (Nezha `mintTransferTool` was Host-as-template-variable, DeepSeek Harness was Host-as-auth-gate — this is Host-as-**persisted-setting-lifetime**): the attacker-chosen value is latched by whichever request wins the cold start. Sweep on authorized assessments: send `Host: attacker.tld` variants during/restart-adjacent to boot, then observe *any* mail/webhook/config surface for the poisoned value; the read-back channel here is email, and email bodies in error-debug modes carry scope dumps (session cookies, config secrets). Same audit question for any app that derives defaults from the first request: which settings are initialized lazily from request fields?
- **Nested-form child resolution must prove parent membership.** Posted-PK child lookup with no parent binding is the either-end edge-addressing family (PraisonAI dependency edges, Gitea URL-repo authorization) applied to ORM nested attributes; the composite-key variant — **new rows keeping request-chosen keys** — is the request-selects-identity leaf. Probe battery for any nested create/update form: post your own parent's child key (control), another tenant's child key (IDOR), a new composite key (identity selection), and a `delete` flag on the foreign row; diff stored state.
- **Header-trust "fixes" without peer checks are still open.** The 4.1.2 dev-tools "local restriction" compares **client-supplied headers** instead of the TCP peer — the guard-implementation fingerprint rule: before accepting an IP/locality gate, determine whether it reads socket peer or header string (`X-Forwarded-For`-shaped bypass), then verify the exposure itself (`/wheels/*` settings/datasource/route disclosure is recon gold; remotely started tests that write the **primary datasource** turn a read primitive into data corruption against the real app).
- **The CLI/MCP second face of frameworks.** p9x9 names AI-agent-via-MCP-tooling as an input source for values that shell out on deploy hosts and CI runners. Standing rule for agentic engagements: any framework CLI exposed as MCP tools inherits the trust its CI inputs never had — branch names, release/version strings, and package contents were already attacker-influenced in Git-hosted workflows; the CLI just stopped escaping them. Reproduce only with inert marker values in disposable repos/hosts.

## Validation workflow (authorized scope only)

!!! warning "Lab CFML stacks and inert proofs only"
    Run Wheels at a vulnerable band in a disposable Lucee/OpenBD install with a **throwaway datasource** (never a real primary DB for the test-context probes), synthetic tenants, and your own mail sink (a mailbox you control).

1. **Fingerprint first:** `.cfm` URL shapes, `cfx_*` cookies, and a GET sweep of `/wheels/*` (settings, environment, routes, migrator) anonymously; record whether datasource names/routes reflect. Then repeat with spoofed `X-Forwarded-For: 127.0.0.1` / `X-Real-IP: 127.0.0.1` to test the header-vs-peer leaf.
2. **Test-context battery:** request a protected/normal route four ways — clean, `X-Wheels-Test-Context: x`, cookie `WHEELS_TEST_CONTEXT=x`, and a test-runner path fragment in a **query parameter**. Evidence: response-context difference, maintenance-mode verdict table, and a pre-exhausted rate bucket on the normal path that resets through the selector (synthetic limiters only).
3. **Scope-replacement probe:** two lab tenants A/B; with an app that scopes by tenant, call a scoped key-finder route with B's row key from A's session: diff exists/read/update/delete verdicts (expect the advisory's replace-semantics); confirm the `exists()=true` oracle with an out-of-scope key under production error suppression.
4. **Nested-children matrix:** own-parent child (control), foreign child key (expect denied post-fix), new composite key (check stored id), `allowDelete=true` + foreign child (check row state, never real deletes).
5. **Host-boot-poison:** restart the lab app, first request `Host: <your-sink-domain>`; trigger a benign error; confirm the error mail routes to your sink; record what the body discloses at default debug settings (redact any cookies in evidence).
6. **Quote-grammar differentials:** `test''` (Oct 15 leg) and backslash forms `test\'` / `\\` in login/reset/lookup identifiers plus BETWEEN/LIKE ESCAPE-adjacent params on lab app code; grammar error vs clean miss is the fingerprint. Keep payloads to error-triggering shapes, never data-exfiltrating unions against anything but your own synthetic tables.
