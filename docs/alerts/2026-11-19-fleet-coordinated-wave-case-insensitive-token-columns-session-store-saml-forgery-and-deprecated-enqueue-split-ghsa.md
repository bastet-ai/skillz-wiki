# Fleet wave (5 GHSAs): case-folded token columns, session-key SAML forgery, and unlogged MDM enqueue

Source: hourly offensive-security scan, 2026-11-19. Primary entries: FleetDM security advisories [GHSA-2r75-q53f-v8px / CVE-2026-130757](https://github.com/advisories/GHSA-2r75-q53f-v8px), [GHSA-94f5-6j6w-r3rh / CVE-2026-130759](https://github.com/advisories/GHSA-94f5-6j6w-r3rh), [GHSA-5vr5-74q2-mfg4 / CVE-2026-130758](https://github.com/advisories/GHSA-5vr5-74q2-mfg4), [GHSA-75wx-4347-854m / CVE-2026-130762](https://github.com/advisories/GHSA-75wx-4347-854m), and [GHSA-fv3p-h7wv-2jgm](https://github.com/fleetdm/fleet/security/advisories/GHSA-fv3p-h7wv-2jgm) (all published 2026-11-18T21:31Z; the GitHub `advisories` copy of the case-collation leg is [GHSA-w2j5-h59q-2h8v](https://github.com/advisories/GHSA-w2j5-h59q-2h8v)).

**Wave in one line:** the MDM management plane leaked its own trust model in five places, token entropy defined by a MySQL collation, IdP trust material read out of an attacker-writable session store, an authorization list that is not the operation list, an ORDER BY oracle for observer users, and an incomplete metadata-escaping fix that left the Homebrew ingester unpatched.

## The five legs

| Leg | Confirmed detail (from vendor advisory) | Operator value |
| --- | --- | --- |
| Case-insensitive security tokens, critical, `< 4.92.0` | `invites.token`, `email_changes.token`, `local_mfa.token`, `sessions.key`, `host_device_auth.token`, and the Apple ADE enrollment profile token lived in `utf8mb4_unicode_ci` columns looked up with plain `=`, so **any case-mutation of a valid token was accepted as the original**. Highest-impact path: confirm a victim's email-change with a case-mutated token, email redirects to attacker, then password reset completes ATO; invite tokens redeemable with the invited role up to Global Admin. A prior fix (4.89.0) hardened **only** the password-reset token. | Storage collation is part of the token's entropy. A 32-character token collapses roughly 2^26 case variants into one accepted value. Case-normalized copies of a token (case-folding mail clients, proxy/server logs, OCR of screenshots, manual transcription) are live credentials on these columns. |
| SAML SSO session-store key confusion, critical, `4.71.0` to `< 4.88.2` (band tails 4.89.3/4.90.3/4.91.2/4.92.3) | The SSO callback looked up the in-progress SSO session by a **client-supplied identifier** with no format check and no session-namespace confinement, so the IdP metadata used to verify the SAML response could come from data an attacker had placed in Fleet's session store. Two low-tier principals could plant that data: any user who can run **live queries** (team-scoped observer+ counts) and, less reliably, a holder of a reusable **enroll secret** with no Fleet account. Present a self-signed SAML response, log in as **global admin**. JIT provisioning on means attacker also mints a new admin account. | Trust material must never be fetchable from a store a low-privilege feature can write. "Read-only" capabilities that allocate storage (live query is a *read* feature that writes session rows) are store-write capabilities. Fix shape: server-minted keys get a prefix plus expected-format validation before lookup. No backport for 4.71.0 through 4.87.x; multi-replica deployments stay open until *every* replica is patched. |
| Deprecated MDM enqueue authorize/operate split, high, `< 4.92.0` | `POST /api/latest/fleet/mdm/apple/enqueue` authorized the caller against the teams of host records that *resolved* from submitted `device_ids`, then enqueued the command to the **raw list** from the body. Unresolved IDs skipped authorization and were still queued: enrollments deleted from Fleet but still enrolled, and macOS user-channel enrollments on other teams (whose enrollment IDs are not host UUIDs). One own-team UUID rode along. **No activity log entry** was produced. | Batch endpoints must authorize the exact set the operation consumes, not a resolved subset. Diff every deprecated endpoint against its non-deprecated twin (`/commands/run` had it right); deprecated surfaces routinely skip guards added to the live path, and the missing audit line is a defense-evasion finding in its own right. |
| `order_key` ORDER BY oracle, high, `< 4.92.0` | `GET /api/latest/fleet/software`, `/software/versions`, and the host-filtered listing passed `order_key` into `ORDER BY` after sanitization but **without an allowlist**. Observer-level users could sort by columns absent from the response, probe column existence through error responses, and with `host_id` set, order by joined `hosts` columns such as the host **node key**. Sorting plus pagination is a binary-search oracle for column values. | Fleet's third same-product ORDER BY leg (the two 4.84.1 enrollment-secret oracles are already on this wiki). Sort parameters are a standing oracle class on inventory platforms; joined-table columns are the payload, and node keys/enroll secrets reached this way convert an observer login into a device-identity capability. |
| Homebrew cask metadata into root scripts, high, manifests generated before 2026-08-19 | Fleet-maintained app install/uninstall scripts for macOS were generated from Homebrew cask metadata with **partial escaping**: cask metadata containing `$(...)` reached scripts running **as root** on managed macOS hosts. The sanitization added for CVE-2026-26191/CVE-2026-34387 covered the admin-upload path and the **winget ingester but not the Homebrew ingester**. Attacker needed the crafted metadata to pass upstream Homebrew cask review plus Fleet's ingestion PR review. | Fix-diff parity failure: one escape-the-input bug fixed at two of three ingester sites. Any package-metadata-to-generated-script pipeline needs an escape-every-interpolation-site audit across *all* ingesters (brew, winget, upload). Two-stage review is the precondition to price in the report; the generated script is the sink. |

## Durable rules

1. **Ask what the column collation is before trusting token entropy.** Any token compared with SQL `=` inherits the column's case/Unicode folding rules. Audit query: `SHOW FULL COLUMNS` (or schema dump) on every token/key/session/reset column; anything not `*_bin`/case-sensitive is a bug waiting for one case-folded leak. The "earlier fix covered one token" history is the fingerprint: fix one token column, grep the schema for sibling token columns.
2. **SSO flows that key pending-authentication state on client-supplied IDs need format plus namespace checks, and the verifier's trust material must live outside any attacker-writable store.** The reusable probe on any Fleet-like console with SAML/OIDC: identify every low-privilege feature that writes to the shared session/cache store (live queries, enroll endpoints, upload temp areas, diagnostic buffers), then test whether the login callback's session lookup accepts keys those features created.
3. **Deprecated endpoints are the sibling-parity test.** For every API with a `deprecated` marker, diff authorization scope, operation target set, and audit logging against the replacement. The authorize-resolved/enqueue-raw split generalizes: batch operations that filter input for *validation* but reuse unfiltered input for *action* are the same shape.
4. **Sort parameter with no allowlist = column oracle; joined-table sort = cross-table oracle.** Prioritize on any platform where Observer-like roles exist; error-response column-existence probing plus pagination binary search is a complete read primitive.

## Replayable validation boundaries

- Disposable Fleet lab instance at a vulnerable band (e.g., 4.91.x), synthetic org/team, marker tokens you generated. Never test against a Fleet server managing real hosts.
- Collation leg: on a lab DB, confirm token columns' collation via schema introspection, then prove case-mutation acceptance with a *self-owned* invite: issue invite, request with uppercased token copy. No third-party accounts, no real email-change flows.
- SSO leg: own lab with SAML SSO enabled and a synthetic IdP you control; verify whether the session-lookup key accepts values not produced by the login flow (e.g., planted via the lab live-query feature with a synthetic team). Proof is authenticating as your own synthetic global admin with your self-signed response, on your own instance.
- Enqueue leg: synthetic team, one own-team host UUID plus a disposable lab enrollment ID you created; positive = command queued for the unresolved ID with no activity entry. Do not send `InstallProfile` or any config profile to devices you do not own.
- ORDER BY leg: lab software inventory with seeded marker values in a known join column; sort-by-invented-column and record error-shape differences only. Do not extract real node keys.
- Homebrew leg: static review of your own generated manifests for unescaped interpolation (`$( `, backticks, `;` inside name/version/URL fields). Do not publish crafted cask metadata; upstream review gates make a disclosed chain a coordination item, not a live payload.
