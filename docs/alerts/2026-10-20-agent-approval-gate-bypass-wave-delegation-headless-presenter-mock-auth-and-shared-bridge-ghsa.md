# Agent approval-gate bypass wave: delegation legs, headless presenters, mock auth shipped to prod, and shared-bridge sandboxes (2026-10-20 03:32Z coordinated GHSA cluster)

Source: hourly offensive-security scan, 2026-10-20 03:32Z GitHub Advisory wave (landed in the 08:1xZ scan) — a coordinated multi-product disclosure against the Python agent-framework ecosystem (Letta, DB-GPT, Coze Studio, LangAlpha, EvoScientist, OpenSRE, piflow, Langchain-Chatchat, Aix-DB, JoySafeter; CVE-2026-77926–77938 and CVE-2026-109440–109444 bands). Durable because ~15 advisories describe **the same three defects wearing different framework hats**: (1) an approval/human-in-the-loop gate that is enforced only in the *interactive presenter* path and silently absent in every other execution context, (2) identity resolved from a stub/mock/header that production ships verbatim, and (3) a "sandbox" that is a subprocess with the parent's environment on a shared network. This page is the approval-gate enforcement-context catalog the May 29 PraisonAI page started, completed across ten products at once.

## Durable operator rules

1. **Approval gates are per-execution-context, and every non-interactive context is the bypass.** Two fresh mechanisms this wave: *delegation legs* (EvoScientist — the child/async task is spawned without the parent's `interrupt_on` map, so the same dangerous tool that pauses for a human inline runs unattended when deferred) and *presenter legs* (OpenSRE — the headless deployment wires a presenter object whose `execution_allowed()` is hardcoded `True`, so the approval UI exists but its answer is pre-baked). Audit rule for any agent framework with human-in-the-loop: enumerate **every path by which a tool call reaches an executor** (inline, async/sub-agent, headless/CI presenter, API-driven, scheduled/cron agent, webhook-triggered) and check each one consults the real approver; then test the approve-benign-inline / abuse-deferred sequence the PraisonAI page already cataloged, plus *never-approve-inline and fire it deferred*. Grep fingerprints: `interrupt_on` / `interrupt_after` set at one construction site but not the sub-agent constructor; presenter classes with `execution_allowed`/`confirm` returning constants.
2. **Mock/stub identity functions ship to production.** DB-GPT's `get_user_from_headers` is a mock that returns admin for everyone — a test fixture on the request path. Grep any agent/LLM platform source for `mock`, `fake_`, `get_user`, `default_user`, `admin` returns on auth-dependency functions; from outside, fingerprint by calling an admin-shaped endpoint unauthenticated and scoring 200-vs-401 (the missing-handler-auth oracle again). Chain note: mock-auth + unsandboxed `code_interpreter` = zero-credential root — on recon, treat an exposed `/chat*`, `/tools/call`, or `/react-agent` route as a candidate pre-auth shell before crediting the login wall.
3. **The sandbox boundary is environment + network, not just filesystem.** Letta's `LocalSandbox` inherits the parent's `os.environ` (every cloud/provider key readable through an "innocent" tool run) and LangAlpha's tenants share Docker's default bridge with inter-container communications on (one tenant's code exec = direct sockets to every neighbor container). Validation battery for any hosted agent sandbox you're authorized to test: (a) print the env inside the sandbox — keys present = boundary fail regardless of path jail; (b) enumerate RFC1918/link-local neighbors on the sandbox network and probe well-known ports — reachable sibling containers with no service auth = cross-tenant read; (c) check for a secrets file convention (`.vault_secrets.json`, mounted tokens) inside the workspace itself.
4. **Import-filter regexes are deny-lists, and Python gives infinite spellings.** Coze Studio's code nodes blocked bare `import os`-style strings but `__import__('subprocess')` passes — same shape as the Flowise `importlib \b`-boundary and `chr()` bypasses (Aug 4 page) and the PraisonAI `find -exec` allowlist-embedded-runner (May 29 page). Sweep order for a code-node filter: `__import__`, `importlib.import_module`, `exec(open(...).read())`, `os.__dict__`, `sys.modules['os']`, `builtins.__import__`, string-concatenated module names. Prove with an inert marker (file write / echo), never destructive commands.
5. **Tenant binding must be checked on the *object*, not the request envelope.** Coze's IDOR accepts your own `spaceID` alongside a foreign `workflowID` — every route in the family (save, update_meta, batch_delete, canvas, **test_run, nodeDebug**) honored the pair. Either-end-addressing rule restated: on any parent-child resource API, run your-ID × foreign-ID × both-foreign decision matrix across every verb, including the *debug/test* verbs which are the forgotten, often less-gated siblings. `test_run`/`nodeDebug` also convert a read IDOR into an *execution* IDOR — score them first.
6. **Self-asserted identity headers are the cheapest auth bypass in the fleet.** Letta's `user_id` header is trusted even in secure mode — no token, just a name. Standing probe on every agent-platform API: re-run one authenticated read with only the identity header changed to a second lab tenant. Header-is-data-not-identity family (DeepSeek Host gate Oct 19, Nginx UI node secret Oct 9), new carrier: plain custom user-id header.
7. **Compose/quickstart files ARE the default security posture.** Letta's shipped `compose.yaml` omitted the env var that installs auth middleware — "follow the docs, get an open admin panel with arbitrary-Python execution" — and DB-GPT/Aix-DB/piflow/Langchain-Chatchat all shipped root-in-container + default DB creds alongside. For product assessment: deploy the vendor's own compose file in a lab, diff which middleware/gates exist vs the env-flag inventory in `.env.example`/docs; for live targets, these stacks fingerprint on route shapes (`/v1/tools/run`, `/api/v1/chat/react-agent`, `/tools/call`, `/dify/get_answer`) — score unauthenticated POST acceptance as a pre-auth RCE candidate with inert canaries only.

## Validation boundaries

Own lab deployments of each framework via vendor compose only; two synthetic tenants with disposable data; inert markers (`touch`, echo-to-file, benign env dump of *your own* synthetic vars) for exec/env proofs; owned callbacks for SSRF-adjacent legs. Never enumerate or connect to real sibling tenant containers outside a lab you operate, never read live provider keys, never run commands beyond inert markers on shared hosts. Cross-tenant proofs require two accounts you own.

## October 21 18:3xZ follow-up: webhook-gateway identity via composite string — colon in a route name escalates toolset authorization ([GHSA-4h98-2jhp-qgm2 / CVE-2026-114463](https://github.com/advisories/GHSA-4h98-2jhp-qgm2), Nous Research Hermes Agent webhook platform gateway)

The gateway builds the session `chat_id` as `webhook:{route_name}:{delivery_id}` and later **re-derives the authorizing route by splitting that string**. A route name containing `":"` resolves toolset authorization to a *different, higher-privileged prefix route* than the one actually authenticated — an attacker holding the target route's HMAC gains the higher route's toolsets. The signature check passes; only the identity re-derivation is wrong.

Durable rule for this page's family (shared-bridge / identity-carrier legs):
- **Composite identity strings that are later re-parsed are authorization input, and every attacker-influenceable segment must be delimiter-free (or the parse must be prefix-anchored on trusted fields only).** The generalization of the wiki's "credential routing keys must be session-scoped" rule from JSON-RPC ids to stringly-typed identities: grep for `split(":")`/`strings.Cut`/`parts[1]` on any field that participates in an authz decision, then test delimiter injection through *every* segment of the composite (here, the operator-chosen-but-attacker-reachable route name). This is the same genealogy as the MCP TS SDK id-routing leg (routing by JSON-RPC id alone) — replace "id" with "concatenated identity" and the probe is identical: does the re-derived identity match the authenticated one?
- Probe shape on any webhook/relay gateway with a delivery-id or channel-id scheme: register (in a lab) a name containing the join delimiter that re-prefixes onto a privileged namespace, deliver with the low-privilege route's valid signature, and observe which toolset/permission set the executor loads. HMAC-valid-but-misrouted is the pass condition.
