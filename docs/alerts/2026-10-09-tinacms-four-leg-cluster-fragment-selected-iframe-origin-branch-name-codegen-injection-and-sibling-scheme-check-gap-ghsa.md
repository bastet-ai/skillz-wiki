# TinaCMS four-leg cluster: the admin's own URL fragment picks the iframe origin and its postMessage trust anchor, git branch names escape codegen string literals, and a sibling markdown renderer skips the scheme check its twins all have

**Signal:** GitHub Security Advisories published a four-advisory cluster against TinaCMS and adjacent packages at **2026-10-09T20:56Z** (CVE-2026-108258 through CVE-2026-108261). TinaCMS is a headless CMS whose admin app is a browser-side GraphQL client holding the editor's content token — the critical leg converts one phished link into full content-API read/write as the editor. Each leg is a reusable class with a fingerprint.

!!! warning "Authorized validation only"
    Lab TinaCMS site with synthetic content and your own editor account; attacker page and observer origin you own. Never frame a real admin into an origin you don't control or submit writes to a live content API.

## Durable operator rules

1. **Fragment/router-splat values that become frame or channel trust anchors are OAuth-grade security state.** The TinaCMS shape — URL fragment → iframe `src` → *also* the `expectedOrigin` compared against incoming `postMessage` — means the "trusted peer" for the message bus is chosen by the attacker's link. Audit any app that (a) takes a destination from fragment/query/hash routing and (b) uses `postMessage` with an origin it derived from user input: the two uses fail together. Probe in a lab admin: craft `#/~//<your-observer>/`, watch whether the frame loads and whether it receives/has-trust-for the message channel (verify against your own observer page only).
2. **Fingerprint the protocol-relative hop.** `/${userValue}` where the value begins with `/` is the one-keystroke class: `//evil` becomes scheme-less-absolute. Any string concatenation producing a URL from a splat/param deserves a leading-`//` test — hash routers hide it from server logs entirely (fragments aren't sent), which also means WAF/server-side controls never see the payload.
3. **Build-time string interpolation of VCS metadata is code execution.** Branch names, tags, commit messages, and remote URLs that reach codegen templates need `JSON.stringify`-class escaping, not concatenation — grep generators for `'${...}'` patterns fed by `git` env vars. PoC boundary: inert marker expressions in your own repo's generated client; never ship an executable payload through a PR to a third party.
4. **Sanitizer-coverage diff inside a single render function.** The pattern "DOMPurify runs on node type X, returns, and node type Y's URL fields never pass through any check" is the same sibling-parity disease as this morning's Vikunja wave: enumerate every DOM sink in the renderer (`href`, `src`, `poster`, `style`, `formaction`) and test each with a scheme canary; verify the sanitizer's *coverage set*, not its presence.
5. **Disabled-feature handlers are still routes.** Shiny's restore ran with bookmarking *disabled* — check whether "off" configuration gates the handler or only the UI. The two-filename existence oracle is a low-severity but reportable primitive; the same "config says off, code path lives" shape recurs across the CMS/dashboard pages on this wiki.
