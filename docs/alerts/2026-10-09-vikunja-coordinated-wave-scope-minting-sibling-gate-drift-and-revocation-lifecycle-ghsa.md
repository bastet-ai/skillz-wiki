# Vikunja coordinated wave: scoped tokens mint unscoped sessions, sibling endpoints disagree on every gate, and revocation misses the artifacts that carry live access

**Signal:** GitHub Security Advisories published a coordinated ~25-advisory wave against [Vikunja](https://github.com/go-vikunja/vikunja) (self-hosted todo/project manager, Go + Vue) at **2026-10-09T20:40–20:57Z**, spread across fix bands `2.4.0`, `2.6.0`, and unfixed-at-publication. This is the **third separate Vikunja wave** (Aug 2 principal-type/cross-object page, Aug 28 write-path FK page, now this one) — each wave exposed axes the previous one didn't, which is the same-product re-sweep rule earning its keep. The wave's unifying operator lesson: Vikunja has *parallel surfaces for everything* — v1 vs v2 API, REST vs CalDAV vs WebSocket, single-read vs list, scoped token vs OAuth vs link share — and **almost every leg is one surface enforcing a control its sibling forgets**.

!!! warning "Authorized validation only"
    Disposable instance, synthetic users/projects/share links, marker-only rows, recorder/rollback for every mutation. Never enumerate a public instance, retain tokens, or touch real users' credentials/sessions.

## Durable operator rules

1. **Credential-minting flows are scope-escalation targets — enumerate what a scoped token can *ask the server to issue*.** A token whose only granted scope is "call the authorizer" defeats the entire scope model in two requests because the *output* of the minting flow isn't bound to the *input's* scope. On any API with scoped tokens + an OAuth/refresh/token-exchange flow: hold a minimal scope, attempt every issuance endpoint, then replay the issued credential against out-of-scope routes. Report the exact scope → minted-capability ladder.
2. **Sibling-surface parity is Vikunja's entire defect genealogy — and it generalizes everywhere.** v1 vs v2 routes, REST vs CalDAV vs WebSocket, list vs single-read, create vs delete, read vs disable, hashed-token storage vs plaintext: in every leg, one surface enforces and its twin doesn't. Build the parity matrix *first* on this product class: every control you confirm on surface A gets an immediate negative test on surface A′ (older version prefix, alternate protocol, sibling verb, sibling route shape). The Aug 2 page (principal collision, view-load), the Aug 28 page (body-FK rebinding), and this wave are all instances of the same audit algorithm.
3. **Permission checks must consult stored state, not caller-shaped objects.** The zero-value fall-through (delete handler hands the gate a `{ID, ProjectID}` stub whose `Permission` field defaults to `Read`) is a grep target: find every `CanX`/policy call whose argument is constructed from request input rather than loaded from the database. Differential proof: perform the operation against a high-permission stored row with a principal that the *stored* value should deny but the *zero* value admits.
4. **Authorization-cache and cache-key hygiene at the policy-voter layer** (Vikunja's sibling leg is the Contao voter below): any memoized allow/deny must key on *(principal, object, action)* — a boolean cached per-principal leaks the first object's answer to every object the request touches.
5. **Revocation is a lifecycle battery, not an endpoint.** Enumerate every artifact that carries standing access — webhooks, share links, sessions, WS connections, tokens, expanded relations, learned UIDs — then test each revocation path (member removal, session delete, TOTP enable, share revoke) against each artifact. Vikunja shipped a cleanup routine *with a stated invariant* whose row set omitted exactly the two live-channel tables, and wired it to 1 of 4 paths. Read the vendor's own cleanup/`ON DELETE` semantics as an inventory of what they knew to revoke; the omissions are the bug.
6. **Ship-default browser trust survives into production when config *appends* to defaults.** `localhost:*` + `AllowCredentials` + a credentials-bearing cookie endpoint reachable by any local page = local-origin token theft (malware, malicious desktop apps, or any XSS on a localhost dev service you also run). Check every self-hosted app's CORS/config defaults for wildcard-origin-with-credentials and note whether the mandatory public setting replaces or joins the list.
7. **Read-vs-step-up asymmetry on secret material:** wherever a secret-bearing resource gates its *destructive* action behind re-auth, test the *read*. The TOTP-secret-after-enable leg is the reusable probe: any second-factor enrollment flow that leaves the secret retrievable by bearer-token alone converts token theft into durable 2FA cloning.
8. **Zero-privilege preconditions can widen blast radius.** The fail-open recalculation triggers *because* the user has no accessible projects — audit the "empty result" branch of every scoped search; empty-scope collapse to unscoped is a repeat fail-open shape (see the Sept 18 ignored-scope page lineage).
9. **Same-product re-sweep validated a third time:** three Vikunja waves in ten weeks, each a new axis family on the same codebase after the previous wave's fixes. When a product has proven advisory velocity, re-test its sibling surfaces after each fix band rather than assuming the wave exhausted it.

## Replayable validation boundaries (lab only)

- **Scope-ladder harness:** create a token scoped only to `oauth.authorize` → attempt the authorize/token exchange → replay the minted JWT against one out-of-scope read route. Evidence: 403-vs-200 pair scoped-token/minted-token against identical routes. Redact all token values; report scope JSON + route decisions.
- **Parity matrix runner:** for each confirmed control (share list admin-gate, v1 login throttle, REST relation gate, v1 user-search rejection, bucket dual-side FK check), fire the same synthetic request at the v2 route, the CalDAV verb, the WS endpoint, and the zero-value-prone verb (DELETE). Deliverable = route-decision table, positive and negative controls on a patched build.
- **Revocation battery fixture:** attacker user creates webhook + link share + WS connection inside a victim project as a member → removed from team → then poll webhook delivery, replay share, hold WS open after `DELETE /sessions`. Marker-only payload; capture which channels survive which revocation path.
- **CORS posture (own instance):** from a page served on `http://localhost:<any-other-port>`, `fetch()` one authenticated read endpoint with `credentials: include` and then the refresh endpoint; evidence = response readability + JWT issuance, on your instance only.
- **TOTP-extraction probe:** own account, own token; confirm secret field presence in `GET /settings/totp` post-enable. Never test against another user's token.
